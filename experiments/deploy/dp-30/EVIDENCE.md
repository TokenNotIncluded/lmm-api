# 记录合同与核对边界

每次运行使用全新的目录和 `run_id`。`manifest.json` 记录完整源 SHA、共同负载摘要、预算摘要、环境类型、实际节点限制和各项能力证据。每行 JSONL 必须携带同一个 `run_id`。所有单位写在字段名或合同中。

## 必需记录

| 文件 | 内容与关键字段 |
|---|---|
| requests.jsonl | 每个计划请求一行。`request_id`、`attempt`、`outcome`、`latency_ms`、`first_byte_ms`、完整终态、按顺序的内容块摘要、完整内容摘要及独立预期值。保留拒绝、超时、取消和本地丢弃，不只保留成功请求。 |
| upstream.jsonl | 从受控上游独立导出的每次调用。含 `request_id`、唯一 `upstream_attempt_id`。不能从客户端请求数复制而来。 |
| ledger.jsonl | 实际数据库流水。含 `entry_id`、`transaction_id`、`request_id`、账本余额桶 `account_id`、有符号整数 `delta_units`、`account_revision`、`balance_after_units`。 |
| tasks.jsonl | 最终任务状态和真实副作用回执。含 `operation_id`、`effect_receipt_id`、`state`。本文件不是不加筛选的状态历史；每个已提交副作用必须保留独立回执。 |
| auth.jsonl | 用标签代替秘密。覆盖 `session`、`api_key`、`revoked_key`；每个标签有 `before`、`after`，记录 `allowed` 和独立规则生成的 `expected_allowed`。 |
| releases.jsonl | 每轮发布记录。含 round、component、不可变摘要、requested/download_start/download_end/ready/cutover/old_stop_accept/drained/cleaned 的毫秒时间和 forced_kill。所有时间均来自同一个观察器的单调时钟。 |
| resources.jsonl | 每节点、每轮及清理后的采样。含容器总内存、RSS、虚拟地址、共享页、缓存、CPU 累计用时、受限用时、连接、旧进程、镜像字节、日志字节、磁盘可用量、事件积压。 |
| faults.jsonl | 故障类别、注入时间、服务恢复时间、恢复是否持续、注入是否已撤除。没有看到恢复时用 null，不能写 0。 |

`templates/manifest.json` 是缺失状态的模板，不是成功报告。可运行的格式示例由 `tests/test_dp30.py::dataset` 生成。该示例所有阶段时间和资源值都是**人工数据，仅用于核对器测试**。

## 金额与持久状态

本分支账本单位为 `credit_500k_usd`。流水用整数，禁止浮点。规范化后的 `account_id` 指账本余额桶，不是用户 ID。以各账户修订号排序；不能把 journal ID 当成全局提交顺序。

先保留同一数据库快照中的余额和修订号。结束后再次保留。核对每笔分录、每笔 journal 的和、每个中间余额以及最终快照。每个请求的预期净变动来自独立的价格/消费记录，不能直接抄实际扣款。重复扣款即使借贷仍平衡，也必须失败。

另外保留预留、capture/release、操作幂等键、确认提交、后台事件和重启恢复证据。当前核对器会检查流水与预期净变动，但不会仅凭这些记录宣称全部持久结算已证明。读真实 PostgreSQL 的适配器尚未提供。禁止用生成的配平分录冒充数据库记录。

模型负载不自动重试。核心对内部数据库命令的恢复必须沿用原幂等标识，并单独核对。正常的失败前路由尝试应写入场景的预期上游次数；不能为了通过测试事后修改预期值。

## 时间、资源与统计

跨节点不相减墙上时钟。控制器记录的是其观察到的阶段回执时间，包含通信开销。要求更精细的节点内部时间时，记录独立时钟域，不混算。

延迟包含失败和本地拒绝。报告样本量及 p50/p95/p99，使用最近秩。吞吐应报告固定到达时间表中的成功数和完整观察时长，不用健康页吞吐、仅成功请求平均值或最大并发替代。

记录 `instance_id`、版本、每实例接纳序号、停止接纳时的序号和在途清单，供实际入口适配器核对。当前通用核对器尚未完成这一版本接纳规则的自动审计，不能声称旧实例已拒绝全部新工作。

CPU 百分比应由同一 cgroup 的累计 CPU 用时差和间隔计算，并按配额说明归一化。RSS 与 cgroup 总量不能相加当成独立内存。采样最大值不是连续真峰值；同时记录内核峰值计数和采样间隔。性能工具自身开销需另设对照，当前本机数据未分离这一开销。

资源达到阈值时停止增加负载和接纳发布；保留错误、等待、存活旧版本、下载占用和积压。磁盘短期平稳不证明无限运行有界，还需实际保留规则、硬配额和清理失败后的恢复。

## 套件仍需完成的工作

单次核对不能证明三次对照完成。最终集成运行需要清单列出所有组、重复编号和原始目录；对比源 SHA、构建参数、输入到达时间、流时长、预算、节点类型和故障点。基线与正常更新分别至少三次；八种故障和强制死亡另组报告。

当前没有多节点驱动、发布或故障执行器，也没有实际应用导出适配器。尚未实现自动套件验收或生产频率推导。工具不会把缺少这些项目的结果提升为整站通过。

核对器验证的是提供的记录，不认证记录来源。最终验收必须同时保留源、构建与镜像摘要、数据库导出过程、节点限制、隔离规则和观察器日志，不能只提交一份把 capabilities 改成 true 的 JSON。
