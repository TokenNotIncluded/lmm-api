## 这轮改动

v2 的入口确认只存在于 Python 替身。v3 在 Rust 中新增
`lifecycle/ingress.rs`，并由 `main.rs` 接入请求检查。

入口先登记一次性票据，再把目标地址和票据交给 Nginx。
Rust 在调用业务处理器之前，先持有 `WorkLease`，然后向入口确认接入。
这样，确认接入所触发的停止信号不会把已经接入的请求当成空闲状态。
票据确认失败、缺失、重复或格式错误时，不调用业务处理器。

配置确认服务后，缺少票据不能退回普通接入模式。确认服务只允许显式的
回环 HTTP 地址；不使用环境代理，不跟随重定向，不传递用户的授权头。
确认请求最多同时 64 个，每次有连接和响应时限。这不是模型请求重试机制。

原来的停止顺序修订保留：HTTP 停止接入并完成响应，所有请求和完成任务的
持有标记释放后，再停止内部 RPC，最后释放保留的身份数据库对象。
**真实结算还没有接入这些持有标记；本轮没有修改账本算法。**

## 接入前取消

v2 中已选中、但没有确认接入的请求可能一直占用退出条件。
本轮先试验了 Nginx `post_action`，实际 HTTP/2 取消测试不通过，故未采用。
失败证据保留在 `evidence/v3-design-probes/post-action-cancel/`。

当前研究适配器读取 Nginx 的私有、追加式请求结束日志。只有看到请求已经结束，
才撤销其尚未使用的票据。即使旧请求稍后抵达核心，确认也会失败，不能发送上游 POST。
已经确认接入的工作不在待确认表中，不会被这个处理取消或重放。

入口待确认表默认最多 64 项。超额时拒绝新的选择，不无限积累。
已经进入退出流程的版本不能重新成为流量目标。

**没有结束记录时，不把超时当成“已经取消”。** 日志缺失、控制器死亡或
请求状态无法确认时，保留有限的待核查状态，并阻止旧实例退出。这个行为会
阻塞后续更新，但不会用强杀旧流或重复 POST 掩盖未知结果。

日志适配器仅供研究，尚不支持日志轮转、控制器持久恢复、多入口或跨节点协调。
控制器仍是 Python 内存实现；没有把它称为可用于生产的完整 Rust 发布系统。

## 实际验证

链路：客户端 → 真实 Nginx 1.26.3 → Python 传输替身 → 回环模拟上游。
这不是 Rust 运行证据，也不是资金结算证据。

## Rust 配置与本地检查

可选的三个设置必须同时提供：

```text
LMM_CORE_INGRESS_ACK_URL=http://127.0.0.1:18888/__ack
LMM_CORE_INGRESS_TOKEN_FILE=/private/run/ingress.token
LMM_CORE_INSTANCE=core-a
```

两实例的名称、公开监听端口、RPC socket 和实际运行目录必须不同。
确认服务可以由同一入口提供。票据是一次性接入证明，不是用户身份或支付授权。
入口必须覆盖客户端提供的 `X-Dp22-Admission` 头。

没有配置这三个设置时，保留原有独立核心的行为。
无论是否配置，`/health/ready` 和付费模型保护都没有解除。

```sh
python3 -B experiments/deploy/dp-22/test_proxy.py
python3 -B -m unittest discover -s experiments/deploy/dp-22 -p test_controller.py -v
# 仅在完整本地仓库、已有固定 Rust 工具链及依赖缓存时：
python3 -B experiments/deploy/dp-22/check_rust.py
```

Rust 检查脚本默认离线，不继承资金/数据库/通知设置。本轮它返回 78，原因是
工具链缺失且交付目录为源码覆盖文件，不是完整克隆。
新增 6 个 Rust 测试，加上原来的 3 个生命周期测试，均尚未执行。
即使这些组件测试通过，也不能替代真实 Rust 长流、数据库结算和多实例验收。
