# 未验收项与交接

本文件定义下一阶段的边界，不报告它们已经完成。当前补丁只触及工具市场结果解析及测试，没有抢写其他任务的生命周期文件。

## 21：共同负载与节点总预算

取得共同负载文件、固定提交与构建产物摘要后，再填入 `full-system-plan.json`。未知的磁盘、带宽、CPU 型号、云端“1g”实际字节数保持未知。源码片段、本机容器、虚拟机、多台独立服务器分别记录，不能合并成一个容量数。

完整容量统计先确认请求经过实际认证、转发和 Rust 持久账本。健康页、模拟结算或未启用模块不能通过该门槛。未通过时，模型吞吐、资金正确率和更新恢复时间保持未测，不填零或模拟值。

服务节点只接收预编译、可校验产物。实验构建和分析工具不进入 1c1g 节点的运行依赖。

## 22/23：保留在途与更新预算

提交给生命周期负责人：新旧不同二进制的 PSS 合计明显高于同二进制双实例；双实例容量预算不能用旧旧组代替旧新组。本次没有测真实启动、入口切换、长流完成、持久结算和退出。

等待明确的就绪、停止接新请求、在途数、结算完成/待恢复义务等观测点，不同时重写它们。更新余量必须包含旧进程、新进程、文件页、连接和结算任务；不同角色 cgroup 不重叠地汇总，不能重复加上父 cgroup 或将 RSS 与缓存重复相加。

新请求先获取有界资源名额，满载按既有接口规则拒绝，或在已声明的短等待期限内等待。不要先完整读取大请求再无界排队。已接受请求保留完成所需的缓冲、上游连接和结算预算；不因启动新版本挪走这些预算。完成、取消、超时、异常与结算待恢复均必须释放或转移资源所有权。

验收要记录拒绝率、失败率、成功吞吐和延迟。降低并发、提高拒绝或缩小合法输入范围，不自动算优化。已消费部分不能因取消而免费，也不能因为重试而重复计费。

## 24/25：跨节点权限与持久结算

本地名额只保护本节点资源。账户级配额、资金权限和预留必须由 Rust 及原子持久状态决定，不使用各节点本地余额估计。相同账号换节点、同时命中新旧版本或重放相同请求 ID，不能增加全局允许额度。

测试至少覆盖同一个请求 ID 并发到两个节点、预留后响应丢失、用户撤销后换节点、结算中连接中断。核对实际上游调用、账本条目、冻结与可用余额、恢复义务、审计和连接释放。未知提交结果必须查询或进入持久恢复，不自动重试副作用。Go 不获得核心数据库权限。

完整部署更新期间，连接池预算计入旧/新核心、扩展、事件工作者、管理与恢复连接。TLS 和认证成本都要计入，不能用无认证或明文模式替代实际跨机路径。

## Rust 独立参数对照

基线 `Limits` 是每实例 16 条在途、8 个排队块，每块 16 KiB；三者相乘的 2 MiB **只覆盖排队内容上界**，不包括请求树、SSE 事件、响应累计、TLS、任务栈、数据库或分配器。[S7]

在完整接线可测后，先单独比较排队块 8/4、准入名额 16/8，再比较实际运行时任务和阻塞工作并行度；不一起改变。每项三次同负载、同工具链、同硬限制对照。保持合法输入、输出、工具参数、精度、超时、审计与释放语义不变。任何错误率、拒绝率或尾延迟回退都作为回退报告，不单报内存下降。

本轮没有修改 Rust 参数、实现阻塞池新接口或声称任务数已有可配开关；需要源码接入方确认实际配置入口。

## 交换空间、压缩内存与 CPU 配额

只允许在明确授权的可丢弃虚拟机中做试验；不改当前宿主。先测无交换，再单独测最多 128 MiB 交换空间；另起一组测最多 128 MiB 逻辑容量的压缩块设备，并给物理压缩池单独设预算。不要把压缩逻辑容量加进 RAM。[S8]

压缩数据需同时包含易压缩和难压缩内容，不能只使用本轮重复字符输入来证明压缩收益。记录实际压缩池内存、交换读写、主要缺页、内存等待、CPU、p99、OOM 与恢复时间。任何持续换页、延迟超标、正常流未完成或账本差异均停止。OOM 保护始终保持；不清宿主缓存、不自动调内核、不默认开启写回。

CPU 配额分别测试 1.0 和 0.8 核，固定配额周期并记录受限次数、受限时间和每秒 CPU 使用。CPU 绑核与配额限速不是同一件事。[S6] 本轮只完成绑核组件试验，没有给交换/压缩/配额收益打分。

## 下一轮通过条件

先约定延迟目标和共同负载；未约定则不发布“稳定容量”。完整阶段至少每配置三轮。保持相同到达时间表、请求内容、模型结果与结算期望；统计每个尝试，不能只记录成功样本。

正常负载要求没有新增失败、没有额外拒绝，账本和副作用核对通过，并保留 CPU、更新与恢复余量。过载单独记录有界拒绝和恢复，不能用过载组高拒绝率改善成功请求均值。正式接受优化之前，重测本轮 512 KiB 常驻内存回退及所有首字节回退。
