## 已接通什么

`apps/lmm-extensions/internal/app/run.go` 的 available 列表和注册 switch
均只有 `identity`。配置了核心 RPC 时默认启用 identity；否则默认不启用模块。
商店、支付、工具市场等包存在，但不在这个宿主中运行。
本补丁没有改变该列表，也没有绕过 Rust 身份、权限或资金检查。

`deployment/docker/compose.extensions.yml` 只声明 extensions 服务，
使用独立的 `lmm-extensions` 项目和已有外部网络。它仍绑定固定宿主端口，
没有双实例入口切换或业务级就绪检查。单纯执行 Compose recreate 不是无感切流。

## 补丁内容

`internal/modules/lifecycle.go` 新增宿主生命周期。先准备和绑定监听端口，
再进入 ready。SIGTERM 先进入 draining，停止接受新请求和新工作，
然后等待已接受的工作结束。工作完成必须包含结果的持久记录。
`/health/live` 不依赖 Rust；`/health/ready` 表示 Go 宿主是否接新工作，
不表示资金、模型接口或未注册业务可用。

`internal/app/run.go` 使用此生命周期，先 `net.Listen`，再标记就绪，
最后 `Serve`。排空期间不撤销已接受请求的 context。
新增的工作许可接口不会自动接管各模块的后台任务。
未来宿主调度模块工作时，必须用 `Acquire` 包住一次有界操作，并在持久记录后释放。

`internal/handoff` 是**未自动启用的本机磁盘交接原型**。它不是新支付数据库，
不保存用户余额，也没有接入真实订单或资金操作。
它只演示：回调验证之后持久接收、内容去重、处理权版本号、任务版本号、
旧处理者拒写、外部结果未知时停止自动重试，以及从可信查询结果恢复。

## 存储与副本清单

| 模块 | 指定宿主已注册 | 源码中的存储 | 本轮副本结论 |
|---|---|---|---|
| identity | 配置核心 RPC 后注册 | 核心只读接口；无本地业务数据库 | 可并行候选；真实核心连接、多机 RPC 和撤销一致性未验证 |
| store | 否 | 独立 PostgreSQL；按 shopID 获取事务级数据库锁 | 数据库锁支持跨进程序列化，但不能据此宣布购买、交付和资金链路可多副本 |
| payments | 否 | 独立 PostgreSQL；订单行锁、订单版本、任务租约；回调事件表 | 订单处理有旧租约拒写；事件查询/完成没有同样的处理权版本条件，须联验后才开放多副本 |
| toolmarket | 否 | 加密文件快照；进程持有排他文件锁 | **单写者**。不得复制容器或本地快照来横向扩容 |
| support / assistant / promotions | 否 | 本轮未完整审查 | 不提供可多副本结论，默认不启用 |

支付 `Step` 已检查租约是否还是当前处理者，且重试使用既有操作标识。
`PutEvent` 保存回调证据，`FinishEvent` 只用状态条件而没有处理权版本。
这里是待验证边界，不是已经复现重复扣款的结论。
工具市场已保存执行意图；不确定调用返回 pending，不会直接重做工具调用。
这有利于安全，但仍需要恢复查询与业务接线。

## 分组选择

当前只有 identity 被启用，保留一个 Go 宿主即可，不增加空闲容器。
未来先比较两个候选方案，而不是每个模块一个进程：

- 低内存候选：一个宿主包含所有已正确接线的模块。更新范围大，进程崩溃会影响整个组。
- 隔离候选：常规业务一组，工具/助手一组。同一二进制按模块清单启动；只替换目标组。

以上业务分组是候选，不是现在可复制执行的环境变量配置。
实际进程比较使用 alpha、beta、gamma 三个空测试模块，测得的是宿主开销下限，
不是商店、支付或工具市场加载后的内存。
同一进程中的模块不是安全隔离。两个进程的 RSS 会重复计入部分共享页，
因此同时记录 PSS。最终容量必须重新测真实模块、持久数据和实际负载。

## 本机任务交接规则

1. 对回调验签、确认渠道与规范化内容之后，才调用 Receive。
   写临时文件、同步文件、原子替换、同步目录全部成功，才允许返回接收成功。
   同一键不同内容必须拒绝，不能覆盖原证据。
2. 由可信本机管理者推进处理权版本。每次处理另有任务版本，修改时两者都检查。
   旧进程即使重新运行，也不能保存过期结果。
3. Claim 后、Start 前没有外部调用；此时中断可恢复成 pending。
   Start 在外部操作前持久保存 uncertain。只有 Start 成功，处理者才能调用外部服务。
4. uncertain 不能自动退回 pending。网络报错、响应丢失和“查询暂时没有记录”
   都不能被解释为“没有执行”。可信查询确认结果后才可 Complete。
   外部服务不提供可靠查询时，需要人工核对。
5. 同一外部操作的键和内容摘要保持不变。Complete 检查回执的键和摘要，
   但不替代模块对渠道签名或查询权限的验证。

这个文件原型每次重新读取受锁保护的快照，不使用旧进程的缓存覆盖新状态。
只支持本机私有目录；不支持 NFS、分布式文件系统或跨机副本。
上限为 1024 个任务、每条 64 KiB、快照 8 MiB。没有自动删除去重记录。
超限拒绝接收；不能把它直接当成生产队列或真实 PostgreSQL 适配器。
旧格式读者拒绝未知字段和未知格式号，避免回退时静默丢字段。

## 单写者切换与多副本改造的区别

工具市场保留单写者时，应保持稳定入口不动。旧实例先停止新工作，
等已接受工作记录结果后退出、释放文件锁；新实例取得同一存储后再开放流量。
短暂停接期间回调不能先确认再丢弃：应由已实现的持久入口保存，或返回失败让渠道重送。
本补丁没有在生产入口实现持久缓冲，因此不承诺工具市场零间断。

要让新旧实例同时写业务数据，需要把模块自己的存储改成经过验证的独立事务存储，
并把“领取任务、修改模块数据、记录结果”组合在合适的事务中。
不能只增加一个租约字段或复制容器，就宣布完成多副本。
新 handoff 原型不能与既有业务数据库组成一个原子事务，不能替代这项改造。

## 本机执行

在完整仓库应用补丁后，从任意目录运行：

```sh
python3 experiments/deploy/dp-23/run-local.py --rounds 10
```

仅 Linux；需要本地 Go、支持 race 的编译环境和 Python 标准库。
脚本不下载依赖，不访问生产，不调用 Docker、git、CI 或部署命令。
它在临时目录复制指定 Go 源码，使用独立测试 go.mod 编译，
不会改项目要求 Go 1.25.0 的 go.mod。此次实际使用 Go 1.23.2。
这只验证所复制的纯标准库包，不等于完整宿主、gRPC 依赖或生产入口构建成功。

构建进程使用 GOMAXPROCS=2、GOMEMLIMIT=1GiB；被测进程使用
GOMAXPROCS=1、GOMEMLIMIT=64MiB。后者不是操作系统的硬资源限制。
每个请求有超时，每轮最多两个活动宿主，所有监听均为回环地址。
操作外部服务的测试最多 8 个客户端线程；采样间隔 10ms。
脚本只向自己创建并核对启动标识的子进程发送信号，不按进程名批量结束程序。

结果写入 `local-evidence/`，不进入版本控制。交付的 `evidence/results.json`
是本轮最终运行的摘要；完整原始日志在交付 ZIP 的 evidence 目录。
两个实验二进制使用相同源码、不同构建标识、相同格式 1；
回退只验证此范围，不证明历史生产版本或跨格式降级兼容。
