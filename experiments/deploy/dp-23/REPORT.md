## 进程中断

| 中断点/异常 | 模拟外部效果次数 | 恢复后的结果 |
|---|---:|---|
| 回调持久提交后、确认前终止 | 1 | done |
| 领取后、记录外部操作意图前终止 | 1 | done |
| 记录未知状态后、实际调用前终止 | 0 | uncertain |
| 外部效果完成后、本机结果提交前终止 | 1 | done |
| 本机结果提交后、响应前终止 | 1 | done |
| 暂停旧进程，新进程完成后恢复旧进程 | 1 | HTTP 409 |
| 存储损坏时接收回调 | 0 | HTTP 503 |

**重要边界：**记录 uncertain 后、实际调用前终止的任务保持 uncertain。
它没有外部效果，但新进程不能仅凭“查询没有结果”猜测旧操作未执行。
本轮没有自动重做，也没有把它计为自动完成。这里牺牲自动恢复速度来避免重复副作用。
其余可核对结果通过持久记录或模拟服务的只读查询恢复。

“本机结果提交”指原型的文件同步、替换和目录同步，
不是实际 PostgreSQL 商店/支付事务提交。外部服务每次 apply 都新增记录，故意不去重。
旧进程恢复后的写入返回 409，新结果保持完全相同。
存储损坏时回调返回 503，没有先确认再丢事件。

## 分组与内存

| 布置 | 同时运行宿主 | RSS 合计 MiB | PSS 合计 MiB |
|---|---:|---:|---:|
| 一个宿主，三个空模块 | 1 | 7.05 | 6.48 |
| 两个宿主，按 1 + 2 分组 | 2 | 13.95 | 7.60 |

RSS 合计会重复计入部分共享页。PSS 按比例分摊共享页，不能把二者混为实际独占内存。
更新期间两个进程同时存在时，10ms 采样的 RSS 最高值为
15.93 MiB；
PSS 最高值为 14.77 MiB。
采样可能漏掉更短的峰值，不是资源上限或容量承诺。
杀死一个分组后，另一个分组的 PID/启动标识不变且请求成功。

这些是空测试模块的宿主开销，**不是实际业务模块、Docker 容器或 1c1g 服务器容量**。
此次运行环境为 x86_64 Linux，内存组上限 4 GiB，CPU 配额约 4 核；不是 1c1g。
被测 Go 进程设置 GOMAXPROCS=1、GOMEMLIMIT=64MiB，但未设置独立 cgroup 硬限制。
