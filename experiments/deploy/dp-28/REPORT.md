## 结论与范围

本机原型通过 20 轮连续更新和 34 项测试。发布产物从第 2 轮起保持相同占用；当前版、上一已验证版、一个仍运行的旧版本同时保留。停止该旧进程并释放引用后，可删除其独有内容，留下当前版和回退版。

**这不是实际 Rust/Go Docker 栈的空间验收。** 本轮未运行 Docker、PostgreSQL 或 LMM 模型服务，未测真实入口切换或结构回滚。所用程序是可执行的 C 测试产物，不是空目录或模拟文件大小；系统空间不足、文件节点耗尽和进程死亡是真实发生的。本机 tmpfs 的 fsync 不构成物理磁盘断电恢复证明。

隔离条件：独立用户/挂载/网络空间；tmpfs 上限 16 MiB、512 个文件节点；Linux 6.18.44、x86_64、Python 3.13.5。每包含同一个 16,416 字节原生程序、262,144 字节不同内容、一个版本文件。包长及摘要见 `evidence/artifact-manifests.json`。编译选项见 `evidence/toolchain.txt`。数值不能外推为整站最小磁盘容量。

本次 `df -B1` 与 `du -sx -B1` 都为 1,052,672 字节；`du --apparent-size` 为 837,897 字节。前者分别反映文件系统占用和可遍历实体分配，后者反映可见内容长度。在其他文件系统，元数据、预留空间、稀疏文件、快照、其他目录及删除后仍打开的文件会使它们不同，不能用一个 `du` 总和当完整可用空间。

真实打开后删除测试：文件名已不见，但进程仍持有 1,048,576 字节。账单报告这部分可见占用；关闭描述符后，文件系统才恢复相同空间。不以“unlink 成功”代替“已释放磁盘”。不可见进程会明确列出，报告值是可见范围的下界。

Docker 官方将镜像 SIZE 定义为 SHARED SIZE + UNIQUE SIZE；多张镜像 SIZE 直接相加会重复计算共有内容。本轮离线计划不推算 Docker 可释放物理字节，明确输出 `null`。真实层账单及更新峰值仍需 Docker 环境。[官方说明](https://docs.docker.com/reference/cli/docker/system/df/)

## 空间门槛

本机预检使用当前挂载点可用字节和可用文件节点数；不写死宿主总容量，也不预支未来清理收益。

```text
所需新增字节 = 压缩包按块取整
             + 每个解压文件分别按块取整
             + 元数据/替换状态余量
             + 诊断轮转峰值余量
             + 明示恢复余量
             + 明示业务增长余量
```

首次包的实测长度是 265,826 字节。当前 4096 字节分配单位下，压缩包预算 266,240，展开文件预算 286,720，元数据预算 147,456，日志预算 16,384，恢复 131,072，增长 65,536，总计新增 913,408 字节和 58 个文件节点。

元数据项和恢复/增长项是明示的实验策略，并非整个 Docker/PostgreSQL 业务的测量上限。共享文件在预检中保守按完整展开计入，账单中才去重。真实接入应由 25、27、29 提供挂载点和增长/恢复数据；不能因有本机公式就声称生产空间足够。

预检不是给不协作写入者的磁盘预留。已实际测试其他写入在预检后吃掉空间：复制返回 ENOSPC，当前和回退状态不变。清理连意图记录都写不下时，拒绝执行，不删回退版本换空间。

## 故障实测

| 场景 | 实际观察 |
| --- | --- |
| 容量耗尽 | 在专用 tmpfs 写到 16,777,216 字节；可用字节 0；更新拒绝，诊断明确失败，旧状态不变 |
| 文件节点耗尽 | 512 个名额全部用完；仍有 16,171,008 字节可用；更新拒绝，日志新建失败，不误判为可发布 |
| 预检后磁盘满 | 返回 errno 28；没有假成功；撤掉测试压力文件后可回收所属暂存，再次安装成功 |
| 写入状态失败 | 不切换到未提交版本；未提交产物保留到显式清理，不修改旧状态 |
| 下载完成后 SIGKILL | 子进程退出码 -9；旧版本状态有效；所属暂存可重试回收 |
| 清理中途 SIGKILL / 注入 EIO | 沿已保存的精确删除意图恢复；已不存在条目不会导致重复效果 |
| 完成收据写失败 | 返回失败；重试生成收据；重复提交已完成计划返回旧收据，不再删文件 |
| 恢复前文件被替换或被新进程打开 | 拒绝继续；不删除替换内容，等引用释放后重试 |
| 并发拉取 | 独立进程持有项目锁时，清理拒绝执行 |
| 路径/引用边界 | 符号链接、越界归档、同设备 bind mount、外部硬链接、无标记资源均未被越界删除 |

预检后空间耗尽场景的文件系统峰值为实验上限 16 MiB，包含故障压力文件。删除该**测试压力文件**后，恢复清理观察峰值 614,400 字节（600 KiB）；随后重试安装峰值 1,150,976 字节（1124 KiB）。这不是原型清理未知宿主数据的行为。

故障原始数据在 `evidence/fault-evidence.json`。34 项测试全部通过，其中 31 项为本机原型测试，3 项为离线 Docker 规则测试。诊断容量和事件资格检查不表示真实服务已接入这些规则。

## 删除、保留与回退证据

首次安装、20 轮更新和旧进程退出后的正常清理共执行 215 条文件/目录删除。每条实际路径在 `evidence/actual-deletions.csv`，包括阶段和理由；它们不是估算列表。中断、故障重试的额外实际清单位于 `fault-evidence.json`。

正常轮次只删除不再引用的旧版本、其独有对象和所属下载暂存，不删除任何 `protected/`、`backups/` 内容或其他项目资源。每轮保留理由见 `retained-versions.csv`。六个原始保护文件的 SHA-256 在每轮前后核对不变；新增的模拟业务记录完整保留。

每轮都重新启动上一版测试程序，校验版本及载荷。第 20 轮成功启动 `r019`；故意损坏回退文件时，更新和回退检查均拒绝。首次安装明确没有不存在的“上一版”。

**尚未验收：**实际 Rust/Go 镜像安装及 20 轮峰值；Docker 层删除后的实际释放量；真实流量和结算排空；PostgreSQL 空间故障与恢复；结构兼容回滚；完整宿主进程视图；物理盘断电恢复；多挂载点容量汇总。此补丁不得因此标记整站磁盘生命周期验收完成。

开发中曾发现共享程序的进程映射会错误保护所有旧版本硬链接，导致清理停滞。现按实际引用路径保护版本、按实体引用保护共享内容；带 `r000` 长期运行的 20 轮实验持续验证这一点。提交的证据是修正后最终运行，未混入中间失败结果。
