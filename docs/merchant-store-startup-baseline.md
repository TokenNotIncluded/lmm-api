# Single-provider startup baseline

The ordinary production deployment contract still requires a genuinely changed
Go provider and a distinct, qualified retained provider. Capability zero,
unknown capabilities and providers below the active floor are refused. A
startup baseline is a separate format 2 authority for the finite first
conversion; it grants no ordinary package install or rollback permission.

The canonical wire contains one official provider and the live closure of both
registered origins, ArchDmit and DmitUbuntu. The authority digest covers every
origin's stopped legacy generation, ordered startup hash, exact admission
bytes, loaded nginx worker generation, business role, physical database/schema,
actual floor and strict five-field status hash. There is no caller `approved`
flag, selectable closure pathname or automatic floor following.

Commands use the existing root-private capsule directory and configured nginx
drop-in. Only `baseline-close` and `baseline-seal` accept `--repo`; they reuse
the official issuer, package layout, source/tag and payload verifier. Explicit
`baseline-rebind` uses that same verifier for a confirmed successor. Stage
candidate assets under the existing fixed `assets/candidate.*` names. First
conversion also requires the exact old official package under
`assets/preactivation.*`. These commands do not download or install packages.

| Action | Observed authority and effect |
| --- | --- |
| `baseline-close --id ID --repo REPO` | Requires the actual official old running PID/ELF/config and missing gate with the 15-table pre-variant inventory. Saves private pre-change facts; installs the separate canonical 503/Retry-After barrier using the native admission owner; checks this origin's own TLS listener and drains accepted backend sockets. |
| `baseline-capture --id ID` | Read-only. Requires normal old process exit, empty cgroup, no remaining client backend in the physical database, no reserved ACTIVE row and a loaded persistent pending startup hook. Reads actual business-role database/catalogs, executes the signed candidate's status and `migrate --verify`, and repeats startup/schema/admission checks. |
| `baseline-seal --id ID --repo REPO` | Contacts both fixed SSH origins twice, checks the installed official candidate ELF and actual captures, then creates new private `state/sealed-HOST.json` files. It never constructs an ordinary candidate/retained plan. |
| `baseline-rebind --id ID --repo REPO` | The same live sealing checks, but only for an explicit confirmed predecessor. Initial seal rejects successor provenance; rebind rejects missing predecessor provenance. |
| `baseline-bind --id ID` | After the reviewed native first-conversion owner copies the exact host wire to `capsule.json`, rechecks the local closed capture and replaces only the persistent hook's pending hash with that canonical capsule digest. Reloads systemd and rechecks the loaded ordered startup seal. Does not start or install a provider. |
| `baseline-confirm --id ID` | Requires actual MainPID/invocation/ELF/status/schema/readiness and the holder's success receipt, written only after its physical session completed exact owner CAS. Refuses remaining ACTIVE rows and requires admission still closed. Creates a new private confirmation receipt. |
| `baseline-confirmed-capture --id ID` | Read-only reobservation of a confirmed baseline, including the current invocation's successful holder/CAS provenance. |
| `baseline-reopen --id ID` | Holds one actual physical shared fence across both confirmed origins' fixed SSH checks, restoring the exact protected original nginx bytes and final writer/readiness/floor recheck. Failure after writing restores and probes the canonical closed barrier; unproved restoration is reported. |

The reviewed first-conversion deployment owner remains responsible for stopping
both old writer units, persistent mask-to-hook handoff, package installation
and explicit shop-only schema commands. It must prove all writer inventory and
old-package preactivation recovery on a fresh production-shaped copy before
execution. None of those operations is authorized by format 2 or by a local
component test. A pending hook is the exact persistent file
`90-merchant-startup-baseline.conf`; it uses a 64-zero capsule hash while stopped.
Absence of a matching capsule blocks startup across retries and reboot.

The one typed hook uses `ExecStartPre=+` because the signed service keeps
`DynamicUser=yes` while the native holder must read root-private authority and
write its durable state. Capture and every runtime check require the matching
sole `ExecStartPreEx` command with exactly `flags=privileged`, the exact
root-owned 0644 persistent hook bytes and its loaded `DropInPaths` entry. Both
the privilege semantics and the normalized hook bytes enter the startup seal;
only the separately validated capsule digest self-reference is normalized.
The main `serve` command retains the signed service's unprivileged hardening.

Baseline package identity is read from the official archive's strict
root-owned `.PKGINFO` metadata so Ubuntu does not need pacman. All subsequent
official signature, source/tag, layout, compiled marker and payload checks are
shared with the ordinary verifier. Ordinary package installation still requires
its real `pacman -Qp` evidence. Both hosts require bsdtar; Ubuntu provides it with
`libarchive-tools`. Fixed native tools use only explicit root-owned executable
paths and their admitted distribution aliases, never an arbitrary PATH entry.

Initial missing to floor 1 is an explicit Option write, not preservation of an
existing floor zero. Shop-only prepare and activation use their own physical
session with exclusive deployment fence before migration lock. Never hold an
outer exclusive lock or ACTIVE owner while invoking those children. Baseline
seal/bind does not call main migration apply or pass financial preparation keys.

For a successor, close with `--predecessor-id PREVIOUS_ID` while the previous
baseline is still actually confirmed and its old floor remains current. The
same official provider is required. The owner then stops the guarded writers,
performs the separately qualified floor change and prepares the new pending
hook. Capture/rebind derives the new actual floor/status/schema and binds the
confirmed predecessor digest. Old status seals stay stale and refused; no
background update follows the floor. Admission may remain closed throughout.

Per-start execution reuses the existing real systemd ControlPID/invocation,
dedicated shared physical PG lease, ACTIVE claim, actual new MainPID/readiness
and same-session exact CAS. A crash retains ACTIVE permanently. Neither a
baseline nor confirm/reopen clears an unknown owner, authorizes an old provider,
or retries a failed start by inferring the installed binary.

Qualification boundaries are deliberate: parser fixtures establish rejection
and canonical bytes; an owned PG cluster establishes real role/session/CAS
behavior; owned systemd units establish real pending-hook and generation
behavior. Full official package through both host profiles and successful
holder/MainPID/readiness/CAS still requires the published signed artifact and a
fresh owned production copy. A test ELF is never called an official provider.
