# 商店客户管理与客服对话

入口：`/store/support`。商品页提供「联系卖家」，订单页按当前身份提供「联系卖家」或「联系买家」。商店导航提供消息入口，更多菜单提供客户管理入口。

## 使用流程

买家可以在下单前就商品发起咨询，也可以围绕自己的订单联系卖家。卖家可以从销售订单或客户列表发起售后对话。同一个买家对同一商品的咨询会复用会话；同一个订单也只建立一个会话。下架商品的已有订单仍可进行售后沟通。

消息区区分买家与卖家视角，支持未读筛选、历史消息、已解决状态、重新打开和对方已读状态。消息正文只按文字显示，不执行 HTML 或 Markdown 中的链接。发送失败后保留草稿及请求编号；重试相同内容不会重复发送。切换会话保留本页面内的独立草稿，切换账号清除页面状态。不将会话草稿存入 localStorage。

客户管理仅显示当前卖家的注册买家和咨询者，包含历史订单数、历史已支付总额、最近订单、联系入口、标签及私有备注。已支付总额是退款前的历史总量，不等于净收入，也不扣减已退款金额。未付款或取消订单仍计入订单数。备注使用版本检查，旧窗口不能覆盖其他窗口已经保存的修改。

## 内置助手

在会话内选择「助手帮助」，可整理问题、起草回复或建议处理步骤。服务器只提供当前参与者有权读取的最近十条消息，每条最多约五百个字符，以及基本订单状态。不会自动附带客户备注、提货码、库存、支付链接、邮箱、账户密钥或网关配置。

用户先检查并可编辑准备提供给助手的文字，再将它放入现有助手输入框。该动作不会自动提交给模型，也不会向买家或卖家发送消息。助手继续使用现有模型配置和权限，不另建供应商连接。助手输出是草稿，用户检查后自行放入客服输入框并发送。退款、发货、调价、承诺赔偿均不由此入口执行。

对话与商品标题属于不可信资料，不作为助手的操作指令。现有助手敏感信息过滤仍会应用，但不能保证识别任意格式的秘密；用户应在预览中删除不需要提供的内容。助手请求队列沿用现有助手机制，不属于客服草稿存储。

## 权限与数据

身份只来自现有登录中间件，不接受调用方指定的发送人或卖家身份。会话只对实际买家和卖家开放，平台管理员身份不会自动取得私人对话权限。客户记录以卖家和买家共同定位；某卖家的备注不向其他卖家、买家或客服助手上下文提供。

消息正文与私有备注使用现有持久化加密机制。部署继续需要有效的 `MERCHANT_STORE_ENCRYPTION_KEY` 或现有回退加密配置；不要替换已有加密密钥，否则历史内容无法解密。密文及内部索引不返回浏览器。相同请求编号的重试在解密后比较原文，不额外保存可用于猜测短消息的明文摘要。

单条消息及私有备注最多 4000 个字符。最多十个标签，每个最多 32 个字符。写接口限制请求体大小。客服限流按已登录账号计算，不占用登录、支付等关键操作共用的 IP 额度：每分钟最多创建会话 20 次、发送消息 60 次、确认已读 180 次、修改状态或客户资料合计 30 次。各类别独立计数；同一网络的其他账号不会共用这些额度。超过额度返回 429 和 Retry-After，发送草稿仍会保留。

消息读取与已读确认分离；打开 API 历史记录不会自动将全部消息标记为已读。已读位置只能前进，必须是该会话中实际存在的消息。浏览器只有在页面可见且最新显示的消息进入视野后才提交已读确认。

## 数据库与部署

本功能实现于当前 Go 后端和 Web 前端，不修改正在进行的 Rust 核心迁移。

增加三个独立表：会话、消息、卖家客户记录。它们通过 `MerchantStoreSupportModels()` 接入正常数据库迁移与校验，并进入旧的快速迁移列表。它们不加入历史商店 `MerchantStoreModels()` 注册表，不提高商店写入阶段，不改变既有支付、库存或钱包表的约束。

先按项目现有流程应用数据库迁移并验证，再部署 Go 后端，最后发布前端。仅更新前端不能启用这些接口。生产使用只读结构校验模式时，必须先由迁移进程创建新表；HTTP 请求不会创建或修补表。

## 当前范围

仅支持已登录的注册买家与卖家。访客订单不会因提供订单号、邮箱或登录另一个账号而取得会话权限；访客身份接入需要另行实现经过验证的订单绑定。没有把未验证的访客订单聚合为一个客户。

当前支持文字沟通；没有附件、邮件通知、离线推送、客服人员分配或自动代发。当前会话每五秒刷新，会话列表每十二秒刷新，页面在后台时不持续轮询。历史分页独立显示，避免拼接遗漏消息。AI 摘要只使用上述有限的近期上下文，并非完整历史总结。

测试入口：后端 `TestMerchantStoreSupport*` / `TestMerchantStoreCustomers*`，包括账号级限流测试；前端 `support-helpers.test.ts` 与 `support-interactions.test.tsx`。实际执行结果和未覆盖范围记录在 PR，不以添加测试文件代替运行验证。
