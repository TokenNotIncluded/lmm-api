# Business extension acceptance still required

The old single-server qualification tests cannot execute after their database, router and models have been removed. Their removal does not demonstrate that replacement business modules work. The following behaviors must receive executable tests when the corresponding Rust commands and Go modules are implemented.

- Paid tools: separate buyers, client identities and authorization scopes. Duplicate calls must not charge twice. Concurrent reservations must respect balances and all applicable budgets.
- Settlement: concurrent completion, expiry, refund and cancellation must yield one valid accounting result. A late job must not undo a later committed state. Each change must have an audit record.
- Team funds: platform administration is not permission to spend team money. Team keys cannot fall back to personal wallets. Membership removal and rejoin cannot restore old credentials or reset budget consumption.
- Payments and shops: provider callbacks must be deduplicated. Prices and payment sources must be fixed per operation. Refunds must use the original source. Go cannot directly edit core balances.
- Streaming: extension shutdown, upgrade and overload must not break an accepted core stream or its settlement. A core crash requires a separately tested recovery design.

Executable repository coverage includes Rust identity/account schema and authorization tests, Go host/client tests, shared Protobuf contracts and Docker process-isolation tests. It also includes the [Commerce process test](../services/core/tests/commerce_process.rs) and its [isolated runner](../tests/commerce/verify_process.py). An independent local execution exercised real Core and Go processes with separate PostgreSQL databases: order payment, duplicate requests, settlement, refund and reconciliation after a lost refund acknowledgement and actual process restarts. Its frozen source inputs were independently byte-bound to commit `707842d`. This is a single personal order using synthetic credits, not complete inventory, receipt, external payment or store qualification.

Separate independent local evidence against frozen `707842d` covers real Core TCP HTTP/SSE with an isolated PostgreSQL database and a controlled synthetic upstream: personal/team payer isolation and permitted fallback, denied and duplicate requests, competing budget reservations, preservation of missing-usage holds, client disconnect and terminal-checkpoint recovery across actual Core restarts. The original SSE test failure is retained; only the affected case was rerun after correcting its Content-Type expectation. These receipts are local evidence, not a newly clean combined run or external-provider acceptance. The integrated [model-process test](../services/core/tests/model_process.rs) and [runner](../scripts/verify_model_process.py) were subsequently independently compiled and executed with a frozen identity-schema-v4 Core build: six process cases and 28 related model HTTP cases passed, with no ignored or filtered cases and no source drift. The controlled upstream remains synthetic.

Separate scoped acceptance of that schema-v4 build passed 112 distinct identity, MFA and financial-authorization cases. The first attempt of one additional refresh test failed during registration because its synthetic password exceeded the documented limit; correcting only that fixture preserved the permission assertions, and the original failure remains retained. An independent full-Core synthetic backup/restore also passed, comparing 79 tables, 16 sequences, catalog definitions, effective permissions and owners, then checking real identity requests and strict financial replays. These results do not cover historical financial import, production recovery, MFA-key recovery, every browser/CLI journey, or the full repository matrix. The browser cross-tab MFA slice remains under independent repair and re-verification.

Independent default-enabled Core test evidence now combines the frozen schema-v4 product run with the separately rebuilt CLI fixture correction: 529 registered test instances passed, zero failed, and four ignored instances remain unrun. The original CLI failure was replaced by 13 real PostgreSQL/CLI passes; the other unchanged targets were reused rather than rerun. Repeated source-level tests are not separate business capabilities. Original failures, ignored tests, tracking gaps and browser limits remain retained. This result does not include the developing [abuse controls](abuse-controls.md), external providers, complete browser acceptance or production deployment.

Full business acceptance remains incomplete under the [quality guide](quality.md) and the [completion scope](architecture-completion-prompts.md). The broader malformed/truncated/missing-usage SSE matrix, external providers, browser/CLI journeys, resource and installation/recovery acceptance remain separate required work. Existing skipped or unrun checks and open quality debt are not cleared by these scoped results.

The retired Go-only portions of the CLI OAuth, editor/provider registration, profile aggregation, wallet and tool-market workflows have also been removed. Their retained client/frontend checks remain useful but do not verify a replacement identity or financial backend. Native Google login has its own implementation and scoped tests; it does not establish all provider flows or an OAuth2 authorization server. The grants foundation remains unissued, without a production consent/code issuer. Remaining OAuth/grant flows and Go business modules still need their corresponding executable backend and end-to-end acceptance.
