## 范围与方法

生产留存快照截至 2026-10-03 08:26（Asia/Taipei），会话时间覆盖 2026-08-12 至 2026-10-03。只读查询了全部留存会话及历史消息，没有修改生产账户、配置或数据，也没有读取私密卡片密文。

使用 [流式审计程序](assistant-feedback-audit.md) 处理全量消息，规范化后用 SHA-256 简单去重；SQLite 负责排序与去重，不把全量会话加载进模型上下文。规则只提供候选信号，不能把包含“不能”“权限”“错误”的普通说明直接计为缺陷。12 个没有留存回复的唯一回合也不能直接判定为线上失败。

837 段唯一会话分成 140 / 140 / 140 / 139 / 139 / 139 六片，逐批进行语义审阅，并核对当前源码是否已经修复历史问题。六片覆盖记录分别与输入逐项比对：缺失 0、重复覆盖 0。审阅使用限幅文本，49 条长消息有裁剪；重要争议另按会话读取相关片段。没有宣称每条被裁剪长文都逐字完整复核。

原始记录、脱敏候选、审阅文件及覆盖校验保存在仓库外私有目录，不提交用户原文、身份映射或凭证。报告只保留聚合数字及问题概括。自然语言脱敏仍可能遗漏个人信息，因此这些产物保持私有。

## 本轮修复范围

| 槽点 | 对应改进 |
| --- | --- |
| 要求修改昵称，却被告知做不到 | 本人昵称确认表单；包括 L0 的登录用户可编辑，确认后只更新 `display_name`。 |
| 找不到密钥删除按钮，助手只叫用户自己找 | 本人密钥非敏感信息列表、明确选定目标、确认后删除或停用；不向模型或历史返回密钥值。 |
| 只问礼包是否领取，反而进入一次性评估 | 单独的只读奖励状态工具及服务端查询保护；查询不会触发决策、领取或扣除机会。 |
| 已有具体用途，还被引导写旧推荐信、等待管理员 | 跟随现行服务端 L1 注册检查与授权流程；主任务按实际获得 L1 判断完成，历史推荐信保留为只读。 |
| 安装任务未完成，助手不查记录就猜 | 返回服务器任务步骤及安装、配置证明，区别 API 活动、安装证明和连接状态。 |
| 消费为零被说成余额为零，计费额度被称为 tokens | 本人账户工具明确提供 USD 钱包余额及额度单位；钱包、订阅、已消费金额和模型 token 数分别解释。 |
| 接入说明中的“模型名称”吞掉整个任务 | 固定身份回答仅处理身份问题，带配置、接入、礼包等任务的请求进入正常助手流程。 |
| 普通用户被导航到仅管理员可见的模型管理页 | 模型工具及导航指向 `/pricing`；管理员仍可进入 `/models`，并说明目录是模型并集，不是实时健康探测。 |
| 半截代码、空草稿被当完整答案 | 保留上游长度终止原因，明确标记输出不完整，不缓存为完成结果，也不自动重放工具。 |
| 疑似密钥黏在错误 TOML 节名里，脱敏漏掉 | 补充窄范围的嵌入凭证匹配，使用合成样本验证；没有确认历史字符串是有效密钥。 |

另外明确助手没有任意访问用户本地工作区、修改文件或运行测试的能力，不能凭一个项目路径声称完成操作；开源悬赏指南也不再暗示只接受代码，关联仓库且有可验收成果的文档、翻译、测试与设计可纳入。

确认流程另覆盖了中文密钥短名与长名混淆、过滤和分页造成的误选、重复名称、登录失效、目标被改动、并发消费及缓存失效。需要精确选择本人密钥并在浏览器确认，当前开启 2FA 时还需有效验证码；确认卡打开后才开启 2FA 也可补输。验证码不进入聊天。礼包和周折扣的中文完成查询语气也加入只读保护。

## 已有能力与后续核验

签到、站内导航、转人工、CC Switch 私密导入链接和 Codex 的 OpenAI 兼容配置，当前源码已有对应工具及规则。本轮保留历史错误作为反馈证据，没有再造一套重复功能。

仍值得单独核验的方向包括：根据本人 request ID 查询脱敏错误诊断、模型与分组的准确映射、模型分类错误的可执行修复，以及没有上游 `length` 证据的半句或零宽字符回复。历史只有对话文本，没有独立执行回执，助手口头说“已生成”“已消耗机会”不等于数据库实际成功；这些案例不能全部冒充已证实故障。

现有 `first_successful_response` 任务判断使用 `LastAPIActivityAt`，失败处罚路径也可能更新该时间。本轮明确此字段代表活动记录，不把它包装成成功响应证明；改变原任务判据需要另行处理历史迁移及成功调用证据。
