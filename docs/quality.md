# 本地质量检查与独立验收

适用于微服务 WIP。工具保存检查与证据，不参与核心运行，也不授权发布。
日常任务先用[工作指南](agent-workflows.md)选检查；本页用于需要分层记录或独立验收的任务。

> [!IMPORTANT]
> 日常开发不读、不执行本页。逐页清单、协议矩阵、资源验收和缺陷交接只在用户
> 明确要求验收、独立复验或项目收尾时使用，不是每次改动的完成条件。日常改动按
> [适度与停止](agent-workflows.md#适度与停止)交付。

## 先选所需层次

普通文档或技能正文使用 `python3 -B scripts/check-docs-brand.py --docs-only`，
不必为了修改说明运行真实数据库与全组件构建。需要质量工具时直接选所需一层，
不要按 quick → related → full 重跑它们共享的检查。工具本身不自动复用前一次报告。

| 层次 | 当前工具实际执行内容 |
| --- | --- |
| `scan` | 变更、源码疑点、断言删除、敏感配置、债务期限及差异空白检查；不是业务测试 |
| `quick` | scan 加工具自测、源码边界和受影响组件格式；单项上限 120 秒 |
| `related` | quick 加固定核心、路由、计费和 Go 扩展回归，再按范围加入协议/Web/数据库模块；单项上限 600 秒 |
| `full` | 包含前述检查并扩大到所有组件、构建、lint、依赖、CLI、数据库及真实进程；单项上限 1800 秒 |

`related` 即使只改文档也会运行固定核心/Go 回归，不是按文件筛选的轻量文档工具。
`full` 仍记录独立资源与真实业务验收为 `not-run`，不能产生完整通过结论。
选择较小范围只能说明该范围，不得用于冒充已经要求的完整验收。

这些说明不修改检查集合、阈值、期限或失败状态。若已选择某层，不得删掉其中的
命令、断言或报告项来换取通过。鉴权、资金、数据完整性缺口不能作为普通债务豁免。

## 执行

需要完整、可信检出和固定工具链；包括工具要求的干净、已初始化 CLI 子模块。
`--base` 是已确认的本次变更前祖先提交，优先复用任务中已有的审查基点；不是仓库
某个写死的历史 SHA，也不能在提交后改用新 HEAD 隐藏差异。

```sh
BASE="${LMM_REVIEW_BASE:?Set the reviewed pre-change ancestor SHA}"
OUT="$(mktemp -d /tmp/lmm-quality.XXXXXX)"
mise exec -- python3 -B scripts/quality-gate.py quick --base "$BASE" --output "$OUT/quick"
```

将 `quick` 换为任务实际需要的一层；完整验收直接执行 `full` 一次。输出必须为
仓库外的新目录，父目录已存在，不覆盖旧证据。Just 等价入口是 `just quality`。
修改工具代码时单独运行 `just quality-self-tests`；所选聚合层已含它时不再重复。

`--plan` 只列出未执行的检查，退出码为 2，不是通过记录。源码执行中变化会使证据
失效。先固定待测输入，不在检查期间继续写入同一工作树。独立失败应继续收集其他
结果；前置构建失败只阻断依赖该产物的检查。

数据库只能是已核实归属的本机一次性测试实例，显式设置 `LMM_QUALITY_DISPOSABLE=1`。
需要 `DATABASE_URL`、`LMM_STORE_TEST_DSN`、`PAYMENT_TEST_DSN`、`LMM_MK09_TEST_DSN`；
支付库名须为 `lmm_payments_test`，商店库是新的 `_test` 结尾库。localhost 可能是
生产隧道，名称检查不能证明隔离。工具不自动创建这些库，也不读取 `.env`。

支付存储锁等待/连接池超时回归另需 `PAYMENT_DEADLINE_TEST_DSN`，指向已核实归属的
全新空库 `lmm_payments_deadline_test`。测试显式安装 schema，不删除或复用旧表；
在 `services/extensions/internal/modules/payments/pgtest` 下运行
`mise exec -- go test -race -count=1 -run '^TestPostgresStorageDeadlines$' .`。
未配置该专用实例时会跳过，不能计为通过；聚合工具不自动准备此实例。

支付真实进程恢复另有[固定产物入口](../tests/payments/README.md)：默认验证入账COMMIT后
丢失Go本地回执；`--case accepted-proof-expiry` 显式选择真实302秒过期、双产品OS重启
及首次入账恢复。两项已分别独立通过；聚合工具通过不能替代其固定产物回执。过期的原事件
仍被接纳接口拒绝，恢复读取的是Core此前持久接纳的原证明；必须核对原任务键、唯一
回执、准确两腿账本和重放后资金不变。定位用 `markref context payments.proof-expiry`。
这不覆盖真实供应商checkout/refund或支付独立资源验收，不能代替完整支付验收。

Go 的 `go test ./...` 不跨嵌套模块；完整计划另检查现有 pgtest 和新增 Go 模块。
缺工具、实例或产物需报告并处理，不能换成 mock 后宣称等价验收。外部供应商可以
模拟，应用内部身份、权限、订单、路由和资金链路不能用固定成功对象替代。

## 结果与复用

`report.json` 记录源码、基点、工作区摘要、命令、目录、退出码、耗时和日志摘要。
工作区摘要含提交差异、暂存/未暂存、新文件、权限及子模块状态，但不完整证明
外部缓存和子模块内部所有字节；后者仍需对应验证。环境覆盖项会记录供审查。

目录为 0700，日志/报告为 0600。被测程序仍可能输出秘密，分享前必须脱敏；不要
把 DSN、Cookie、私钥或生产数据写入证据。复用保留原始源码和真实命令，不能给旧
记录换上新提交。单命令记录工具 `scripts/local-release-tests.py` 不证明集合完整。

退出码：0 是该层自动检查通过；1 是失败、到期或证据失效；2 是受阻、未执行或
中断；3 是必须审查。不得使用 `|| true`、只看最后一行或把 skip/ignored 当通过。
必要集合未执行任何测试也不算通过。quick、构建或语法检查不是完整业务验收。

full 的开放 critical 债务会阻断验收；独立资源与真实资金验收项仍是 `not-run`。
不能导入作者手写的 JSON 让它变绿。真实缺口需要实际执行与独立审查补足。

## 疑点与例外

新增忽略、skip/only、空 catch、临时标记和测试环境分支是待审查线索，不是自动
认定的缺陷。扫描报告新增匹配与删除的断言，保留旧数量；合法测试、注释、示例
和格式调整可能命中。它不是完整语法或语义证明，也可能漏报。逐项说明实际用途
和证据，不为清除线索删除有效测试或添加全局忽略。

`.quality/debt.json` 只记录已确认事项，不自动登记所有关键词。baseline_revision
是来源，不是豁免开关。开放事项在到期前解决或以新证据续期，每窗不超过 30 天。
普通例外不能豁免资金、数据丢失、关键权限或业务正确性缺口。

新增例外的 kind 为 exception，填写明确路径、原因、负责人、风险、问题、替代验证
及退出条件；不得使用通配符或根目录。reviewer 初始 pending，不能填作者自己；
解决事项须附证据。例外不取消命令、不修改退出码，也不隐藏失败。

质量工具、测试脚本/预期、依赖/锁文件、类型配置、工作流、忽略和阈值变化需随
业务代码审查，不能因为检查变绿就免审。本轮指导不改变这些机制。

## 测试与开发分工

业务修复和完整验收应由不同人员或不同 agent 承担。测试方掌握验收标准和失败用例，
开发方不能给自己的修复判定“独立验收通过”。仅换一个 agent 名称、读取作者的
通过摘要，或重放作者手写的结果，不构成独立验证。

- **测试方**：先固定待测提交、产物摘要、配置、角色及测试数据；独立确定预期，
  执行测试、记录缺陷和复验。不在被测输入中修改业务代码，也不顺手修复后自验。
  可以新增测试脚本和回归用例；测试源码须保留并可复现，不能只交一份通过报告。
- **开发方**：依据缺陷修复业务代码，提交补丁、原因分析、影响范围和自测结果。
  可以补充开发回归测试，但不能单方修改独立验收标准或把自测当作验收结论。
- **整合方**：保护并行工作的文件所有权，审查业务与测试差异，固定修复后的提交，
  交回测试方复验。测试方在新输入上通过后，才能将该缺陷标为“复验通过”。

测试与开发使用独立任务和输出目录，不能一边测试一边改同一被测工作树。
优先复用已有隔离检出或固定产物，不为每条缺陷机械创建新分支；共享源码只能由
指定整合方写入。测试账号、库和服务必须与生产隔离，凭据和原始日志不进 Git。
普通验收结果放仓库外；需要长期保存的恢复材料归档到 `~/Backups`。结束后停止
本轮自建服务，核实归属再清理临时库、缓存和重复产物，不能删除他人的活跃材料。

每条缺陷至少记录：待测版本、页面 URL 或协议方向、环境/角色、复现步骤、预期、
实际结果、相关接口状态或脱敏日志，以及修复提交和复验结果。状态分开记录为
“发现问题”“已修复待复验”“复验通过”“受阻”“尚未覆盖”。agent 返回补丁、
测试进程退出、提交推送、PR 合并及生产部署也是不同状态，不能相互代替。

**禁止以改绿代替修复**：不能删除失败用例、弱化断言、增加无依据的 skip、吞掉
异常、隐藏页面或把真实内部链路替换为固定成功的 mock。断言确实错误、需求变更
或协议规格变化时，保留原失败证据和测试差异，说明理由，由测试方独立核对新预期；
资金、权限和数据完整性要求不能因此降级。合法 skip 仍是未执行，不是通过。

这些是分工与验收要求，不是现有工具已经实现了写权限隔离。若同一操作者暂时无法
安排独立复验，只能报告“开发自测通过、独立验收未执行”，不能冒充已完成。

## 逐页验收

按待测版本的路由文件、动态子页面注册表和导航生成页面清单，而不是凭记忆选择
几个页面。包含直接打开深链接、刷新与页内切换；例如 `/dashboard/flow` 必须单独
记录，不能因 `/dashboard/overview` 通过就视为分流页通过。后台页、详情页和弹窗
中的关键操作也不能只验入口页面。按实际权限分别覆盖未登录、普通用户和管理角色。

1. **渲染与响应**：桌面/移动端、明暗主题；检查浏览器异常、控制台报错、失败请求
   和响应结构，不以“截图有内容”或 HTTP 200 单独判通过。
2. **数据状态**：加载、空数据、正常数据、未知/缺失字段、畸形响应、401/403、
   超时及 5xx。加载失败必须与真实空数据区分；未知金额或历史记录不能显示成零。
3. **交互与权限**：筛选、分页、切换、详情、提交与重试，以及拒绝、登出、账户
   切换后的缓存清理。角色、时间范围和账户变化不能复用不属于当前用户的数据。
4. **真实集成**：在隔离环境中连接实际 Core/Go，验证所需接口与业务操作。内部
   权限、路由、订单和账本不能替换；写操作只用合成数据并核对最终状态和幂等性。

mock 用于组件状态、边界条件和可控故障注入，必须遵守真实接口契约；调试 fixture
不是生产兜底。分别记录“组件/mock 通过”“真实浏览器通过”“实际接口/业务链路
通过”。后端未实现、接口返回 503、前置配置缺失或用例未执行，都不能计入页面通过。
原先未覆盖的页面出现错误时，新增能复现该错误的用例，而不是只补成功假数据。

## 协议转换验收

从当前实现和协议说明列出客户端协议 → 上游协议 → 输出模式的矩阵，逐项记录
支持、明确拒绝、失败或未执行。不能用一个成功文本请求代表全部协议，也不能将
历史验证记录当作本轮结果。relay 当前支持范围及有意拒绝的功能见
[relay 协议说明](../services/core/src/relay/README.md)；具体能力以待测源码为准。

- **请求**：模型别名与真实模型映射、消息顺序、工具调用/工具结果关联、参数和
  鉴权转发；不支持的字段或内容必须明确拒绝，不能静默丢弃后声称转换成功。
- **普通响应**：文本、推理内容、工具 ID/参数、结束原因、usage 与供应商元数据。
  缺失 usage 保持未知；检查语义与关联关系，不只比较响应是否能解析为 JSON。
- **流式响应**：用真实 HTTP/SSE 分片验证 UTF-8 和事件边界、增量工具参数、多工具
  关联、事件顺序及终止标记；覆盖截断、畸形事件、慢客户端和流式/非流式一致性。
- **错误与取消**：上游 4xx/5xx、连接/读取超时、断流、客户端取消、大小/队列限制，
  以及敏感上游错误体不泄露。工作结果不确定时不得自动重放可能已执行的请求。
- **应用集成**：外部供应商可用可控隔离服务模拟；身份、选路、预留、结算、失败
  对账必须经过真实应用和隔离库。核对拒绝时不调用上游、取消后的资源回收，以及
  重复请求/最终账本状态。relay 使用测试路由或计费 adapter 的结果不能替代此项。

分别报告解析/编码单测、真实 HTTP 协议转换、实际应用资金链路、真实供应商兼容性。
前三者通过不证明已经测试付费供应商；没有授权与私有测试凭据时不发起真实付费调用。
只跑脚本模拟不能声称已完成持久化结算或生产准入。

## 独立业务与资源验收

lightdot 或其他独立审查者使用完整检出、固定工具链和一次性库，先确认实际范围，
再直接运行目标层。完整目标执行 full 一次，不叠加前两层。对比同一源码/配置的
命令、日志及数据库最终状态；已有匹配证据无需重做，但不能冒充独立执行。

模型、权限、计费、重复请求、并发、失败和流式取消须经过真实应用判断。外部接口
可用隔离模拟服务；内部钱包和账本不可替换为固定成功。未接通链路不能声称完成。

资源比较使用同一机器或相同容器限制、release 构建、配置、数据库与工作负载：

1. 记录源码/程序摘要、CPU/内存限制、编译选项、数据库版本/连接限额。核心单独运行，不依赖 Go。
2. 测启动就绪耗时、预热后空闲 RSS/PSS、线程、文件描述符及数据库连接。
3. 用固定种子、请求量和并发测成功/拒绝/失败、延迟、峰值内存和任务回收；不以全量 503 或减少功能换低内存。
4. 停止负载、排空后再采样；正常退出后核对进程、端口、连接、临时资源及预扣额度。

资源验收必须包含明确的 1 核、受限内存配置，并读回实际生效的 CPU 配额与内存
硬上限；CPU shares/调度权重不等于 1 核配额，Go 内存目标不等于进程或 cgroup
硬上限。记录数据库是否计入总预算，负载生成器和受控上游使用独立资源预算。
Core 单独运行与 Core + Go 扩展分别验证；不能因为 Core 使用 Rust 就跳过扩展的
分配、GC、缓存和后台任务压力。

执行前冻结持续时间、并发阶梯、代表性业务比例、成功吞吐/延迟目标及恢复门槛。
场景须覆盖预热、持续稳态、突发超容量、慢消费者/流取消和停止负载后的排空。
同时保留宿主、cgroup、进程/热点线程 CPU，内存增长、队列/在途上限、连接及
错误码；区分容量拒绝、停机、路由不可用、计费失败与结算待确认，不能把所有
503 都解释成 CPU 保护。验证上限内仍能完成正确业务，超容量时有限拒绝且恢复后
可继续处理；不靠调高保护阈值或删功能通过。资金终态、UNKNOWN、预扣保留及
恢复重放仍按原业务断言核对，不能强制关池或丢任务来制造资源归零。

本地并行测试可用 [`scripts/test-resource-lease.py`](../scripts/test-resource-lease.py)
分配合作式资源。`run --root` 要求已有、绝对路径、当前用户所有且权限 0700 的私有
目录；每次生成独立的 task/nonce 输出、target 与追加回执。子命令必须以
`mise exec --` 开始，stdout/stderr 不转发；测试应将经过检查的诊断写入
`LMM_TEST_OUTPUT`，凭据不得放入命令参数。

`--heavy` 使用已有的当前用户私有目录 `/tmp/lmm-delegate` 中的共享 flock，
不删除锁、不按超时抢占。SIGTERM/SIGINT 取消及写回执失败都会等自有子孙进程退出
再放锁；合作进程不退出时会继续等待，不承诺取消期限。`--socket` 传递已监听的
`LMM_TEST_LISTEN_FD`，子进程须接管该 FD，不能关闭后重新绑定。`--postgres` 只创建
新的固定镜像测试库并核对物理身份、owner NOLOGIN 和低权限 runtime，不接收已有
DSN；runtime 凭据仅给子进程。它不是服务维护锁、沙箱或部署验收结论。

脚本回归使用已有私有目录 `LMM_A09_TEST_ROOT` 执行
`python3 -B scripts/test_test_resource_lease.py`；只有显式设置

### 公共连接与请求头边界

`public_server` 在 HTTP 解析前限制最多64个已接纳的公共 TCP 连接，另允许一个
刚 accept、尚未判定的临时 socket；HTTP/2 多个流共用一个连接，不按流计数。
超额连接立即重置，不创建处理任务。首个请求头从 accept 起有10秒绝对期限，
覆盖静默、慢滴 HTTP/1 请求头和未完成的 HTTP/2 前言；HTTP/1 后续请求头使用
Hyper 原生10秒期限。已解析请求的 SSE、HTTP/2 和升级连接没有新增总时长限制，
原有请求体和停滞写入保护仍生效。升级连接保留名额直到实际 IO 释放。
这不声称为已建立 HTTP/2 连接中的每个新流提供请求头期限。

`runtime.connection-admission` 标签关联实现、协议测试、实际进程测试和
[`verify_public_ingress.py`](../scripts/verify_public_ingress.py)。
脚本接受 `--mode unit|red|green`，要求指定封存 Core、测试程序及各自 SHA256，
同时提供 Core 的 `--source-binding` 和 `--build-receipt`。`--output` 与
`--process-root` 必须是新建、空的私有目录，并确认只由本轮任务使用。
完整参数见 `python3 -B scripts/verify_public_ingress.py --help`。
脚本只创建自有隔离 PostgreSQL，不使用已有站点数据库；失败 fixture 保留供排查。

本轮独立配对验证使用相同测试程序：旧产物出现515个公共 socket FD，
512个测试连接在期限后仍保留内核状态；修复产物峰值64、到期状态为零。
四类原始连接各提供128次尝试，所有512个客户端 socket 在连接前复制保留的
FD/device/inode 均保持到20秒之后的回收检查。两边均通过45个正常模型响应及逐笔资金核账；
修复保留同一条健康 HTTP/2 TCP，且完成实际进程、资源组和成功数据库回收。
六项协议测试另覆盖长响应、升级占位、后续 HTTP/1 慢请求头及正常排空。
实际 Core 限制1CPU/256MiB，生成器和数据库另有预算，不是整机验收。
