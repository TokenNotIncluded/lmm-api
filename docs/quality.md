# 本地质量门禁

适用于微服务 WIP：Rust 核心、Go 扩展、CLI、前端及其协议和构建入口。
这是检查与证据记录工具，不是发布授权。核心不依赖它，也不增加运行时内存。
使用仓库已有的 Python、Git、Bash、Cargo、Go 和 Bun；没有新增第三方依赖或远程工作流。

## 底线

不能删除有效断言、跳过失败测试、缩小检查范围、关闭类型检查或降低门槛来换取通过。
不能在生产代码中加入测试专用成功分支，吞掉异常返回成功，或用空实现冒充完成。
外部支付商、模型和工具可以模拟；端到端验收必须经过真实应用权限、订单、路由和资金代码。
模块测试中的远端接口替身只证明模块行为，不能证明真实资金链路已经接通。

修复应尽量保留修复前失败、修复后通过的证据。重构要核对行为未变；改变契约要说明理由、影响和迁移方式。
兼容性按已承诺契约判断，不能无依据保留兼容层，也不能只凭搜索不到引用删除动态入口。
同一业务规则保持一个权威实现；错误有明确语义，重试有上限，资源有清理，日志不含秘密。

## 执行入口

在完整、可信的本地检出中运行。输出目录必须是仓库外的新目录，不能覆盖旧证据。
`--base` 必须是独立审查者认可的变更前提交；不能在提交后改用新 HEAD 隐藏本次变更。
本补丁的来源为 `bbde7468dcbd08091bc6a666c27946c2a385f2bf`。其他分支应明确选择自己的审查基点。

```sh
BASE=bbde7468dcbd08091bc6a666c27946c2a385f2bf
OUT=$(mktemp -d /tmp/lmm-quality.XXXXXX)
python3 -B scripts/quality-gate.py quick --base "$BASE" --output "$OUT/quick"
```

同一入口也可以写作 `just quality quick --base "$BASE" --output "$OUT/quick"`。
不同轮次必须使用不同目录。单独测试门禁：`just quality-self-tests`。

| 层次 | 内容 |
| --- | --- |
| `scan` | 变更清单、源码疑点、断言删除、敏感配置、债务格式与期限、差异空白检查。不是业务验收。 |
| `quick` | scan 加门禁自测、现有架构边界检查、受影响组件格式检查。单项上限 120 秒。 |
| `related` | quick 加固定 Rust 核心、路由、计费及 Go 扩展回归；按改动加入协议、前端检查。单项上限 600 秒。 |
| `full` | 不按改动路径缩减自动检查集合；包括构建、类型、lint、依赖、CLI、全部核心测试、独立 Go 数据库模块、协议生成物和真实进程检查。单项上限 1800 秒。 |

`full --plan` 只输出未执行的检查，退出码为 2，不能作为执行证据。
完整集合先执行尽可能多的独立检查；前置构建失败只阻断依赖该产物的检查。
`go test ./...` 不跨越嵌套模块，因此完整门禁显式包含现有三个 pgtest 模块，并发现扩展目录中新加的 Go 模块。
被检查的现有业务命令仍来自已有 Cargo、Go、Bun、Python 入口，没有复制业务实现。

数据库测试只允许本机一次性测试实例；设置 `LMM_QUALITY_DISPOSABLE=1` 明确确认。
还需要 `DATABASE_URL`、`LMM_STORE_TEST_DSN`、`PAYMENT_TEST_DSN`、`LMM_MK09_TEST_DSN`。
支付库必须叫 `lmm_payments_test`；商店库必须是新的、以 `_test` 结尾的库。
禁止把数据库名检查当成生产隔离：localhost 也可能是生产隧道，操作者必须核实实例归属。
不自动创建这些命名数据库，不读取 `.env`，不把地址或凭据写入报告。
缺少实例、工具、源码或前置产物要处理阻碍，不能换成 mock 后宣称同等验收。

## 结果的含义

`report.json` 记录来源 SHA、审查基点、工作区摘要、命令、目录、退出码、耗时和日志摘要。
摘要包含已提交差异、暂存及未暂存内容、未忽略的新文件、文件权限及子模块状态。
执行过程中源码变化会使证据失效。外部依赖缓存及子模块内部所有字节不由该摘要完整证明；子模块仍需单独验收。
日志和报告分别限制为私有权限 0600，目录为 0700；日志仍可能包含被测程序输出的秘密，分享前必须脱敏。
工具链与依赖环境仍需按开发指南准备。报告列出可影响运行器的环境覆盖项供复核，不把它们隐瞒为默认环境。

退出码：0 表示该层自动检查通过；1 表示失败、到期或证据失效；2 表示受阻、未执行或中断；3 表示必须审查。
只有 0 是该层通过。不能在外层使用 `|| true`、忽略退出码或只看最后一行日志。
测试运行器报告的 skip/ignored、必需 Go/Rust 集合没有实际执行测试，都不记作通过。
`quick` 通过不等于 `full` 通过；构建成功不等于业务成功。

**完整验收当前还包含外部验收项。** `full` 将资源与真实资金联合验收明确记录为 `not-run`，不会产生完整通过结果。
该状态只能由独立执行与审查补足，不能输入一份作者手写的 JSON 让门禁改成绿色。
当前 WIP 的 QD-001 也会阻断完整验收。这不是声称发现了资金损失，而是防止将未接通的链路当成已完成。

## 疑点、基线和例外

新增忽略指令、skip/only、宽泛 any、空 catch、临时标记和测试环境分支是**待审查线索**，不是自动认定的缺陷。
扫描保留旧数量，只报告新增匹配；同一行重复增加也会被报告。被删除的测试断言单独列出。
注释、示例字符串、合法测试和格式调整可能触发线索。扫描不是完整语法或语义证明；跨行表达式、别名调用等可能漏报。
不能为了消除线索删除合法测试或加入全局忽略。人工复核应说明命中位置、实际用途及验证证据。

`.quality/debt.json` 记录已确认事项，不自动把所有关键词命中登记成债务。
`baseline_revision` 是起始证据来源，不是一个通过基线的授权开关。
变更扫描只统计本次涉及文件的旧线索，不声称完成了整个仓库的技术债清点。
已登记事项要在到期前解决或提交有新证据的续期变更；每次审查窗口不超过 30 天，到期即失败。
资金、数据丢失、关键权限及业务正确性缺口不能作为普通历史债务豁免。

新增例外使用同一记录结构，`kind` 为 `exception`。必填范围、原因、负责人、风险、关联问题、替代验证和退出条件。
`paths` 必须为明确路径，不能使用通配符或仓库根目录。`reviewer` 初始为 `pending`，不能填写作者自己。
已解决事项必须附证据。例外文件不能取消命令、修改退出码、隐藏测试失败或删除新线索；它只是待独立核验的解释。
本补丁中负责人及期限是待审查的交付记录，不代表已经取得独立批准。

对 `.quality`、工作流、门禁和测试脚本、测试预期、依赖清单、锁文件、类型配置、忽略规则及检查阈值的变更单独列出。
这些变更需要审查者与业务代码一起查看，不能因为检查变绿而免审。
不设删行数、测试数量、覆盖率增长目标。复杂度、依赖数、重复版本、包体积及内存用于定位问题，不替代验收。

## lightdot 独立验收

使用完整检出、固定工具链和一次性数据库，先复核本补丁实际范围，再运行三层检查。
对比相同源码/配置下的命令、日志及数据库最终状态。路由、计费的独立路径测试必须与真实宿主联调区分。
真实资金链路接通前，不能关闭 QD-001。权限拒绝、重复请求、并发、失败和流式取消必须使用真实应用判断。
外部供应商可以使用隔离模拟服务；应用内部的钱包和账本不能替换成固定成功的测试对象。

资源验收在同一机器或相同容器限制下，使用相同 release 构建方式、功能配置、数据库及工作负载：

1. 记录源码/二进制摘要、内核、CPU/内存限制、编译选项、数据库版本与连接上限。核心单独运行，不能依赖 Go 进程才能启动。
2. 记录启动到健康就绪耗时；预热后采样空闲 RSS/PSS、线程、文件描述符和数据库连接。
3. 使用固定种子、固定请求量与并发的代表性流量；记录成功、拒绝及失败数、延迟、峰值内存、连接和任务回收。不能用全量 503、减少模型功能或空响应换取更低内存。
4. 停止负载并等待排空，重新采样；正常退出后核对进程、子进程、监听端口、数据库连接、临时资源和预扣额度。进程消失不等于资金和外部资源都已回收。

附原始采样、负载脚本和前后差异，不只提交平均值或百分比。当前交付没有这些测量，不能补写优化数字。

## 本地能做什么，托管平台还需要什么

本地脚本能稳定发现部分问题、检查格式与期限、保存执行结果；不能认证审查者身份，也不能阻止作者改写脚本或跳过执行。
维护者后续可配置受保护分支、必需检查、独立审查、代码所有者审核、禁止自行批准和限制管理员绕过。
门禁、阈值和豁免文件应由独立人员审查；外部检查最好使用受信基点的配置，并验证目标提交与证据对应。
启用哪些远程检查及其运行成本须另行批准。本补丁不改工作流触发器、仓库权限、保护规则，不推送、合并或发布。

已有单命令证据工具 `scripts/local-release-tests.py` 保留不变；它证明运行记录对应的来源，不证明检查集合完整或取得发布许可。
旧 `just check` 仍可用于开发检查，但不是这里定义的完整验收入口。
