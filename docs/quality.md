# 本地质量检查与独立验收

适用于微服务 WIP。工具保存检查与证据，不参与核心运行，也不授权发布。
日常任务先用[工作指南](agent-workflows.md)选检查；本页用于需要分层记录或独立验收的任务。

## 先选所需层次

普通文档或技能正文使用 `python3 -B scripts/check-docs-brand.py --docs-only`，
不必为了修改说明运行真实数据库与全组件构建。需要质量工具时直接选所需一层，
不要按 quick → related → full 重跑它们共享的检查。工具本身不自动复用前一次报告。

| 层次 | 当前工具实际执行内容 |
| --- | --- |
| `scan` | 变更、源码疑点、断言删除、敏感配置、债务期限及差异空白检查；不是业务测试 |
| `quick` | scan 加工具自测、源码边界和受影响组件格式；单项上限 120 秒 |
| `related` | quick 加固定核心、路由、计费和 Go 扩展回归，再按范围加入协议/Web/数据库模块；单项上限 600 秒 |
| `full` | 包含前述检查并扩大到所有组件、构建、lint、依赖、CLI、数据库及真实进程；单项上限 1800 秒 |

`related` 即使只改文档也会运行固定核心/Go 回归，不是按文件筛选的轻量文档工具。
`full` 仍记录独立资源与真实业务验收为 `not-run`，不能产生完整通过结论。
选择较小范围只能说明该范围，不得用于冒充已经要求的完整验收。

这些说明不修改检查集合、阈值、期限或失败状态。若已选择某层，不得删掉其中的
命令、断言或报告项来换取通过。鉴权、资金、数据完整性缺口不能作为普通债务豁免。

## 执行

需要完整、可信检出和固定工具链；包括工具要求的干净、已初始化 CLI 子模块。
`--base` 是已确认的本次变更前祖先提交，优先复用任务中已有的审查基点；不是仓库
某个写死的历史 SHA，也不能在提交后改用新 HEAD 隐藏差异。

```sh
BASE="${LMM_REVIEW_BASE:?Set the reviewed pre-change ancestor SHA}"
OUT="$(mktemp -d /tmp/lmm-quality.XXXXXX)"
mise exec -- python3 -B scripts/quality-gate.py quick --base "$BASE" --output "$OUT/quick"
```

将 `quick` 换为任务实际需要的一层；完整验收直接执行 `full` 一次。输出必须为
仓库外的新目录，父目录已存在，不覆盖旧证据。Just 等价入口是 `just quality`。
修改工具代码时单独运行 `just quality-self-tests`；所选聚合层已含它时不再重复。

`--plan` 只列出未执行的检查，退出码为 2，不是通过记录。源码执行中变化会使证据
失效。先固定待测输入，不在检查期间继续写入同一工作树。独立失败应继续收集其他
结果；前置构建失败只阻断依赖该产物的检查。

数据库只能是已核实归属的本机一次性测试实例，显式设置 `LMM_QUALITY_DISPOSABLE=1`。
需要 `DATABASE_URL`、`LMM_STORE_TEST_DSN`、`PAYMENT_TEST_DSN`、`LMM_MK09_TEST_DSN`；
支付库名须为 `lmm_payments_test`，商店库是新的 `_test` 结尾库。localhost 可能是
生产隧道，名称检查不能证明隔离。工具不自动创建这些库，也不读取 `.env`。

Go 的 `go test ./...` 不跨嵌套模块；完整计划另检查现有 pgtest 和新增 Go 模块。
缺工具、实例或产物需报告并处理，不能换成 mock 后宣称等价验收。外部供应商可以
模拟，应用内部身份、权限、订单、路由和资金链路不能用固定成功对象替代。

## 结果与复用

`report.json` 记录源码、基点、工作区摘要、命令、目录、退出码、耗时和日志摘要。
工作区摘要含提交差异、暂存/未暂存、新文件、权限及子模块状态，但不完整证明
外部缓存和子模块内部所有字节；后者仍需对应验证。环境覆盖项会记录供审查。

目录为 0700，日志/报告为 0600。被测程序仍可能输出秘密，分享前必须脱敏；不要
把 DSN、Cookie、私钥或生产数据写入证据。复用保留原始源码和真实命令，不能给旧
记录换上新提交。单命令记录工具 `scripts/local-release-tests.py` 不证明集合完整。

退出码：0 是该层自动检查通过；1 是失败、到期或证据失效；2 是受阻、未执行或
中断；3 是必须审查。不得使用 `|| true`、只看最后一行或把 skip/ignored 当通过。
必要集合未执行任何测试也不算通过。quick、构建或语法检查不是完整业务验收。

full 的开放 critical 债务会阻断验收；独立资源与真实资金验收项仍是 `not-run`。
不能导入作者手写的 JSON 让它变绿。真实缺口需要实际执行与独立审查补足。

## 疑点与例外

新增忽略、skip/only、空 catch、临时标记和测试环境分支是待审查线索，不是自动
认定的缺陷。扫描报告新增匹配与删除的断言，保留旧数量；合法测试、注释、示例
和格式调整可能命中。它不是完整语法或语义证明，也可能漏报。逐项说明实际用途
和证据，不为清除线索删除有效测试或添加全局忽略。

`.quality/debt.json` 只记录已确认事项，不自动登记所有关键词。baseline_revision
是来源，不是豁免开关。开放事项在到期前解决或以新证据续期，每窗不超过 30 天。
普通例外不能豁免资金、数据丢失、关键权限或业务正确性缺口。

新增例外的 kind 为 exception，填写明确路径、原因、负责人、风险、问题、替代验证
及退出条件；不得使用通配符或根目录。reviewer 初始 pending，不能填作者自己；
解决事项须附证据。例外不取消命令、不修改退出码，也不隐藏失败。

质量工具、测试脚本/预期、依赖/锁文件、类型配置、工作流、忽略和阈值变化需随
业务代码审查，不能因为检查变绿就免审。本轮指导不改变这些机制。

## 独立业务与资源验收

lightdot 或其他独立审查者使用完整检出、固定工具链和一次性库，先确认实际范围，
再直接运行目标层。完整目标执行 full 一次，不叠加前两层。对比同一源码/配置的
命令、日志及数据库最终状态；已有匹配证据无需重做，但不能冒充独立执行。

模型、权限、计费、重复请求、并发、失败和流式取消须经过真实应用判断。外部接口
可用隔离模拟服务；内部钱包和账本不可替换为固定成功。未接通链路不能声称完成。

资源比较使用同一机器或相同容器限制、release 构建、配置、数据库与工作负载：

1. 记录源码/程序摘要、CPU/内存限制、编译选项、数据库版本/连接限额。核心单独运行，不依赖 Go。
2. 测启动就绪耗时、预热后空闲 RSS/PSS、线程、文件描述符及数据库连接。
3. 用固定种子、请求量和并发测成功/拒绝/失败、延迟、峰值内存和任务回收；不以全量 503 或减少功能换低内存。
4. 停止负载、排空后再采样；正常退出后核对进程、端口、连接、临时资源及预扣额度。

保留原始采样和前后差异。进程消失不等于资金和外部资源已回收，没有测量就不写
提速/内存百分比。不以删行数、测试数量或覆盖率增长代替业务结果。

本地工具不能认证审查者身份或阻止作者改脚本。远端保护、必需检查、独立审查和
权限由维护者另行配置；启用远端任务及其成本仍需授权。文档修改不改变工作流
触发器或仓库权限。`just check` 是日常开发集合，不是此处的完整验收入口。
