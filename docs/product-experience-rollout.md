## 实现边界

- API 访问以服务端授权为准；OAuth 不等于绕过访问审批，OAuth 授权不等于成功调用。
- 引导响应新增 `api_key_created`，区分手动 Key 与 OAuth 管理凭据；`details_available` 区分查询失败与确实没有记录。
- 未获取到数据必须显示未知/加载失败，不视为未申请、未调用或零收入。
- 公告阅读确认不是分析追踪同意。滚动到底只能证明界面操作，不能证明用户理解了内容。
- 来源归属不修改邀请和财务记录；历史账号不可伪造首次来源；跨设备仅依赖可靠账号关联。
- 不新增硬编码的模型运行状态、退款状态或价格。没有事实来源时明确说明缺失。

- 新增 `/operations/sources`，位于管理员“运营分析 → 用户来源”。推广链接支持生成、复制、二维码、重命名、归档和分页；`source_test=1` 测试访问不采集。
- 新的浏览器来源采集必须明确选择允许；尊重 Do Not Track。仅保留允许的来源参数、入口页面类别和来源网站主机名，排除 OAuth／付款回跳，不保存原始 URL、IP、User-Agent 或请求正文。
- 随机 HttpOnly Cookie 对应的服务端访客标识做 SHA-256 处理；已关联到一个账号的浏览器历史不可转移给另一个账号。匿名会话同一 nonce 重放不增加来源记录。
- 密码及通用 OAuth 的成功注册路径异步关联来源，500ms 超时，不影响注册成功。后续登录不补造注册来源。首次观察来源与注册来源分开保留，注册回看当前固定 30 天，并记录是否由历史记录归属。
- 推广链接的来源、活动、内容和目标在创建后不可重新分配，重命名／归档只改变显示属性；浏览器实际来源网站与推广标记独立保存。

## 第三批：已确认的调用、留存与账号来源详情

- 文本响应结算路径写入明确的 `acquisition_success_v1` 布尔标记：已写出响应、HTTP 2xx、有输出用量、非 Playground、正常流结束且无请求取消／记录的流错误。处罚扣费、渠道巡检、创建 Key 和 OAuth 授权都不作为成功调用。其他类型请求尚未纳入此口径。
- API 路径不增加统计数据库查询；标记随原有调用日志写入。独立 runtime 任务按分钟读取既有日志、按账号及 UTC 日汇总，不复制正文、IP、凭据或 Request ID。重复请求记录及重复扫描不会叠加活跃账号。
- 第 7 日留存以首次观察到合格成功调用的 UTC 日期为起点，只有第 7 天已完整处理的账号才进入分母。日志缺失区间所影响的账号单独计数，不能当成流失；缺失区间之外的完整批次仍可计算。处理进度、重建状态和未知值会显示在页面和 CSV 中。
- 汇总支持管理员重放恢复；账号自行更改许可不会重置全站扫描进度。数据源丢失且无法从既有日志恢复的部分不补零。正常提交延迟有重叠扫描保护，超出重叠范围的迟到记录需重建；写入失败的缺失标记在进程内汇集后由后台保存，不能将其声称为跨进程崩溃的零丢失保证。

## 第四批：模型详情费用估算

- 模型详情加入单次请求估算，默认输入 10,000 / 输出 2,000 Tokens。用户可选择当前模型与账号共同可用的分组，调整输入、输出和缓存命中 Tokens。

### 第四批续：文本阶梯表达式估算

- 费用估算现在支持 v1 的纯 Tokens 动态表达式，包括阶梯条件和受限数学函数。沿用已有受限表达式解释器，不执行 JavaScript。
- 与后端 `BuildTieredTokenParams` 对齐：`len` 始终是包含缓存的总输入；只有表达式引用 `cr` 时才从 `p` 中减去缓存。即使引用在另一个分支中也保持后端的静态变量识别规则。表达式结果除以 1,000,000 后仅乘一次分组倍率。
- 先检查所有分支，再计算选中分支；含请求头、参数、时间或未知函数／变量的表达式不出估算，避免条件暂时未命中就忽略实际计费所需信息。未知版本、非有限数值和负费用也不出估算。
- 前端 6 项计算测试、类型检查、定向 lint、生产构建及后端 billingexpr/service 阶梯定向回归通过。没有浏览器视觉复核，也没有提交或部署。
- 仍只估算一次纯文本请求，缓存写入、媒体、工具、实时渠道附加倍率以及请求上下文相关价格不在本次估算范围；这些限制继续在页面说明。第 5 项的完整特殊计费模拟和其余待办仍未全部完成。
