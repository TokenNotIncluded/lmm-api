# 微服务架构与状态（WIP）

分支 `wip/rust-core-go-extensions`，PR #675。只用于全新隔离环境；不升级、导入或清空已有数据库。当前不能替代线上服务。

## 谁负责什么

| 进程 | 负责 | 不负责 |
| --- | --- | --- |
| `lmm-core`（Rust） | 身份、权限、账户、资金、预算、订阅、模型路由及转发 | 启动或同步等待扩展业务 |
| `lmm-extensions`（Go） | 商店、工具、助手、运营、支付适配及公开协议 | 自建身份、直接改核心余额、访问核心数据库 |
| `lmm` 客户端 | 连接服务并执行用户操作 | 判断最终权限、在本地决定扣费 |

以上是三个独立可执行程序。`apps/web` 另行构建静态页面，由 Web 服务器提供；核心库的初始化和开发用户创建分别使用 `lmm-core init-db`、`lmm-core bootstrap-user`，不另设管理程序。

源码按服务与用户应用划分，目录名不改变程序、接口或分发包名称：

```text
services/
  core/          # Rust 核心，程序名 lmm-core
  extensions/    # Go 扩展宿主，程序名 lmm-extensions
apps/
  cli/           # 独立 lmm 仓库的 Git 子模块，程序名 lmm
  web/           # React 静态前端
contracts/       # 跨服务协议
config/          # 配置模板
deployment/      # Docker 与部署定义
packaging/       # 发布包定义
scripts/         # 开发与验证脚本
docs/            # 文档
```

核心保持一个 Cargo 项目；Go 业务模块仍在 `services/extensions/internal/modules/`，只有需要独立部署时才拆为服务。目录迁移本身不改变内存占用或核心的独立启动要求。

核心可独立运行，不需要 Go 扩展进程、Go 镜像或 Go 数据库。低内存单核部署见 [核心独立部署](core-standalone.md)。实际使用身份与账户功能仍需 PostgreSQL；未启用正式收费链路时，模型接口维持 503，不能以降低资源开销为由放行免费请求。

核心与扩展独立构建、打包和更新。模块内存与并发限制不能代替进程隔离；不可信代码仍须放进独立进程。单主机故障也不在容器隔离能够保证的范围内。

## 当前源码状态

核心已有身份、团队与权限代码，以及账本、预算、订阅、路由、转发、事件和恢复模块。Go 已有商店、客服、工具市场、支付、助手与运营模块。**模块存在不等于已在宿主中启用，也不等于已通过真实资金联合验收。**

默认宿主只按显式配置启用只读 `identity`。公开协议读取是独立、只读的文件快照，不使用服务凭证，也不调用核心。其他业务模块仍需要最终组装、受限存储连接、权限和资金适配。

空库安装、所有核心 schema 的统一校验、同事务账本与预算处理、实际模型流量和资金接口仍需逐项核实并接通。核心 `/health/ready` 和模型入口保持未就绪，不用临时成功响应掩盖缺口。准确的已执行测试以绑定源码、命令、退出码和日志的本地记录为准，不在本文累计旧测试数字。

## 必须保持的约束

用户、团队、内部账户、操作人和付款方是不同概念。平台等级、平台管理权限与团队角色分别检查。团队 Key 只用所属团队资金；个人 Key 默认只用个人资金。付款顺序和权限由核心决定。

一次收费固定操作人、付款方、价格版本、预算周期和资金分项。权限、预留、预算及事件需要在一致的事务边界内处理；上游流式输出不持有长事务。重试、结算与退款必须引用原操作，不能重新选择付款方。

Go 每个业务模块拥有自己的数据和窄接口，不共享全局数据库对象。身份或计费依赖不可用时，收费操作必须拒绝，不能免费放行。

## 剩余验收

把已有模块接成真实业务，再验证账户与团队隔离、模型调用与结算、支付与退款、重复请求、跨周期处理和进程恢复。单元测试、模拟渠道、真实数据库及真实进程测试分别记录，不能互相替代。
