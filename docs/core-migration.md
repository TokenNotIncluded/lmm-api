# 微服务架构与状态（WIP）

分支 `wip/rust-core-go-extensions`，PR #675。只用于全新隔离环境；不升级或清空已有业务库。旧数据迁移实验必须从只读备份恢复的隔离副本读取，写入另一个新目标库。当前不能替代线上服务。

## 谁负责什么

| 进程 | 负责 | 不负责 |
| --- | --- | --- |
| `lmm-core`（Rust） | 身份、权限、账户、资金、预算、订阅、模型路由及转发 | 启动或同步等待扩展业务 |
| `lmm-extensions`（Go） | 商店、工具、助手、运营、支付适配及公开协议 | 自建身份、直接改核心余额、访问核心数据库 |
| `lmm` 客户端 | 连接服务并执行用户操作 | 判断最终权限、在本地决定扣费 |

以上是三个独立可执行程序。`apps/web` 另行构建静态页面，由 Web 服务器提供；核心库的初始化和开发用户创建分别使用同一个 `lmm-core` 的 `init-db`、`bootstrap-user` 子命令，不另设管理程序。离线命令须显式选择安装账户的 TOML，普通运行使用另一个受限账户；配置路径见[文件布局](filesystem-layout.md)。

源码按服务与用户应用划分，目录名不改变程序、接口或分发包名称：

```text
services/
  core/          # Rust 核心，程序名 lmm-core
  extensions/    # Go 扩展宿主，程序名 lmm-extensions
apps/
  cli/           # 独立 lmm 仓库的 Git 子模块，程序名 lmm
  web/           # React 静态前端
contracts/       # 跨服务协议
config/          # 配置模板
deployment/      # Docker 与部署定义
packaging/       # 发布包定义
scripts/         # 开发与验证脚本
docs/            # 文档
```

核心保持一个 Cargo 项目；Go 业务模块仍在 `services/extensions/internal/modules/`，只有需要独立部署时才拆为服务。目录迁移本身不改变内存占用或核心的独立启动要求。

核心可独立运行，不需要 Go 扩展进程、Go 镜像或 Go 数据库。低内存单核部署见 [核心独立部署](core-standalone.md)。实际使用身份与账户功能仍需 PostgreSQL；模型默认关闭时接口维持 503，必要权限或计费能力不可用时也必须拒绝，不能以降低资源开销为由放行免费请求。

核心与扩展独立构建、打包和更新。模块内存与并发限制不能代替进程隔离；不可信代码仍须放进独立进程。单主机故障也不在容器隔离能够保证的范围内。

13 个安装组件为 identity、oauth-grants、ledger、payments、charging、routing、events、charging-ledger、migration、console、model-gateway、commerce、abuse。安装 schema 不等于启用对应业务；普通启动不创建角色、不授权、不执行 DDL，也不自动升级已有库。

模型验收目前只覆盖服务端明确启用的数字回环合成上游，以及可精确换算为整数 credits 的价格。外部渠道和不支持的计价维度仍拒绝；客户端不能选择上游地址、付款方或报价。流式输出先提交对应证据再发送，缺少最终用量时保留预留款，不以零用量结算。上述测试不证明真实供应商或线上流式服务已经可用。

公开协议读取是由 TOML 配置的独立只读文档快照，不使用服务凭证，也不调用核心。Go 未配置 Commerce 或其他必需权限时，付款操作明确拒绝，不能免费放行。支付证明恢复的联合测试使用合成回调和独立数据库，不代表真实 Stripe/ePay 或退款全链路已经兼容；早期 Rust 服务对象重建不等于操作系统进程重启；后续独立双进程验收的确切范围见上述支付说明。

`/health/ready` 只表示已配置组件通过检查；完整安装但仅启用身份时可以返回 200，同时声明模型和支付关闭。`/health/model-ready` 在模型关闭时返回 503，健康响应不代表上游可用或整站验收通过。准确的已执行测试以绑定源码、命令、退出码和日志的本地记录为准，不在本文累计旧测试数字。

身份迁移脚本 `scripts/migrate-legacy-snapshot.py` 默认仅预览。实验只迁移账号与受控密码验证信息，不迁移旧 API Key、会话、余额或订阅；无法确认的权限和登录方式保持关闭。实际写入要求匹配的来源、目标实例及结构凭据，并验证原子事务、重复执行和冲突拒绝。生产数据、映射、预览和连接信息不得提交到仓库。

## 必须保持的约束

用户、团队、内部账户、操作人和付款方是不同概念。平台等级、平台管理权限与团队角色分别检查。团队 Key 只用所属团队资金；个人 Key 默认只用个人资金。付款顺序和权限由核心决定。

一次收费固定操作人、付款方、价格版本、预算周期和资金分项。权限、预留、预算及事件需要在一致的事务边界内处理；上游流式输出不持有长事务。重试、结算与退款必须引用原操作，不能重新选择付款方。

Go 每个业务模块拥有自己的数据和窄接口，不共享全局数据库对象。身份或计费依赖不可用时，收费操作必须拒绝，不能免费放行。
