# 全新微内核建设计划（WIP）

分支 `wip/rust-core-go-extensions`，PR #675。保持 Draft，不合并、不部署生产、不修改生产数据库。

本分支只面向新安装。旧用户/Key 导入、余额换算、数据库升级、回填和双写切换不再属于计划。没有清空现有数据库的命令，也没有自动迁移或自动修复。新环境必须显式安装全新数据库。

## 当前已落地

Rust 核心位于 `apps/core-rust`，Go 扩展的唯一源码目录为 `apps/api-go`。原 Go 单体和重复的 `apps/extensions-go` 目录已从本分支移除，旧源码可从 Git 历史查阅，不保留为运行时回退。前端和独立 LMM CLI 源码保留，但不能因此推导旧整站 API 仍可使用。

核心已有个人/团队原生账号、平台权限分层、会话和 Key 校验、逐 Key 付款顺序、团队邀请和成员版本、审计事务、全新数据库安装、HTTP 接口及只读 Protobuf 通信。Go 宿主已有显式模块注册、启用列表、服务凭证隔离、每模块并发上限和独立启动关闭。

**Go 当前只接通只读 identity 模块。** 商店、工具市场、助手、客服、推广、支付适配及原控制台 API 尚未按新边界重新实现。删除旧代码不等于这些业务已完成重构。本分支不能替代现有网站。

数据库现阶段只有身份、账号、授权和付款规则，没有真实钱包、账本、预算或订阅权益。额度类型和付款候选不代表扣费功能。核心 `/health/ready` 及模型接口继续返回 503。

## 稳定边界

Rust 独占用户、账号、团队、权限、凭证、资金与模型请求。Go 管理更新频繁的业务模块，每个模块拥有自己的存储和限定接口，不得获得核心数据库凭证。

用户 ID、团队 ID 与内部账号 ID 分开。平台管理员角色、L0–L4 账号等级、团队管理角色、消费与转账权限分开。操作人、Key 归属和付款方不能互相替代。团队 Key 只花所属团队的额度，个人 Key 默认只用个人账号。

未来每个收费请求应固定操作人、凭证、付款账号、价格版本、预算窗口和资金分项。权限验证、预算检查与预留使用核心单库短事务；上游输出不持有长事务；结算和退款再使用短事务完成。重试或退款不能重新选择付款人。

成员授权版本变化不能清零预算累计。订阅周期独立记录，跨周期结算仍引用原周期。资金使用明确整数单位、溢出检查和追加账本；不能直接通过 Go 更新余额。

Protobuf 解决接口和消息格式，不自动保证可靠事件或重复扣款防护。后续需要原子操作去重、事务事件表、扩展侧去重和积压限制。身份或计费不能同步等待 Go 在线。

## 后续实施顺序

1. 完成原生注册、登录/OAuth、会话生命周期、完整团队成员与邀请管理。
2. 完成统一账本、预算、订阅权益、预留、结算、退款、重复请求保护及崩溃恢复。
3. 完成路由、上游转发、协议转换、计量和真实持续输出。
4. 将商店、工具市场、助手、客服、推广和支付适配逐项接入 Go 模块及各自存储，不恢复第二套身份或余额写入方。
5. 完成前端接入、独立镜像发布、旧单体部署资料和其他遗留工作流清理、全站回归及新安装验收。

这不是旧数据迁移顺序。每批仅报告实际已实现和已验证的能力，不用临时 200、空实现或旧后端回退掩盖缺口。

## 上线验收

重复请求只产生一次资金效果，并发请求不能超出预算；退出重入和换 Key 不重置周期累计；跨周期结算、撤销、退款和进程崩溃均有可验证的恢复规则。

扩展停止或更新不能影响核心已接受请求的权限、预留和结算。核心升级仍需多个就绪实例与旧连接排空；单容器和单宿主故障无法保证 token 永不中断。容器 ID 不变不是持续输出验收的替代品。

只使用隔离测试数据。开发 Docker 数据库权限、容量和停止等待参数不是生产默认承诺。操作方法见 [Docker 指南](../deployment/docker/README.md)、[身份指南](core-identity.md) 与 [通信指南](core-protocol.md)。
