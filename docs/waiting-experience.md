# 等待体验

## 交互规则

- 真正有结果时立即显示，不为小游戏延长请求或页面切换。路由 pending 的最短展示时间设为 0。
- 默认等待 4 秒后才出现“等待时玩一局”，用户主动点击后开始。短等待、输入框内的小加载提示不展开游戏。
- 九点“熄灯”只在本地计算，没有网络请求、账户写入、付费动作、音效或奖励。每个棋盘都有已知解。
- 结果开始到达时停止棋盘交互，提供简短状态和“返回任务”。失败、取消、等待结束不冒充业务成功。
- 收起游戏不会停止真实任务。新的任务和同一组件的下一次等待都重新开局，订单和账户/会话之间不共享游戏状态。
- 每格触控区域 48×48px。通关时将焦点送到“换一局”；业务结果返回时可定位实际消息、验证码或短信正文。
- 游戏不属于助手的 `role="log"`，步数变化不会混进对话读屏日志。游戏有独立、简短的结束状态。

## 已接入的等待路径

| 场景 | 接入点 | 结束条件/说明 |
| --- | --- | --- |
| 路由加载 | main.tsx 的 defaultPendingComponent → LoadingState | 路由内容准备好即显示，不设置额外等待时间 |
| 通用整块加载 | LoadingState | 仅整块模式，inline 模式保留小提示 |
| 控制台列表 | DataTablePage | 初始加载或较长刷新；返回表格区域 |
| 设置页 | SettingsPage 数据加载与 Suspense | 复用通用等待层，不阻断设置内容呈现 |
| 模型广场 | LoadingSkeleton | 保留骨架内容和可选小游戏 |
| AI 助手 | Conversation 外的 WaitCompanion | 只等首次非空正文；首段回复出现后返回实际消息 |
| 手机号接码 | SmsOrderDetails | active 且尚无验证码或短信正文；收到哪种内容就定位哪种内容 |
| 邮箱接码 | 当前激活订单 | active 且尚无验证码；返回当前订单区域 |
| 充值报价 | RechargeFormCard | 计算报价期间可选游戏，不调用付款接口 |
| 支付确认处理 | PaymentConfirmDialog | 计算或处理期间，不改变原确认/取消规则 |
| 第三方 OAuth 回调 | OAuthCallbackScreen | 等待既有登录/绑定流程；仍由原逻辑跳转 |
| 开源悬赏与争议列表 | 局部 LoadingState → 通用等待层 | 保留原加载消息 |
| 绘图 | 既有贪吃蛇 | 保留用户开关，每次生成只自动展开一次；手动收起后不立即重开 |

这是当前接入清单。各业务完整流程仍需按全站路由验收，不将“组件已接入”当作所有页面或真实第三方流程均已完成。

## 绘图小游戏交互

方向键监听仅限可聚焦的游戏区域。画布可以通过 Tab 或点击获得焦点；其他页面按钮、输入框及 Ctrl/Alt/Meta 快捷键不被游戏拦截。移动方向按钮使用 44px 触控区，并提供七语言名称。
