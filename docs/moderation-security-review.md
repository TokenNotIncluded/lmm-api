# OpenAI Moderation 异步安全审查

本说明记录内置 AI 助手和 API 安全审计的内容审查边界。公开说明为 [`/legal/safety-review.html`](../apps/web/public/legal/safety-review.html)，当前开关、分组模式和类别金额由站内 [`/security`](https://api.lmm.best/security) 页面展示。静态说明不代表某个分组已经启用审查或扣款。

## 默认关闭与管理范围

新配置默认 `ModerationEnabled=false`、`AssistantModerationEnabled=false`、`ModerationGroupPolicies={}`。没有明确配置的账号分组保持关闭；不能用通配符让所有分组自动进入审查。

- API 安全审计使用 `ModerationEnabled`、`ModerationGroup`、`ModerationModel`。
- 内置助手使用 `AssistantModerationEnabled`、`AssistantModerationGroup`、`AssistantModerationModel`。
- `ModerationGroupPolicies` 按用户实际账号分组指定 `off`、`tolerant` 或 `strict`，以及 `category_fines_usd`。

审查路由分组用于选择已有 OpenAI 官方渠道，不是被审查用户所属的分组。助手和 API 的总开关相互独立；即使某组配置了模式，对应总开关关闭时也不进行该功能的审查。

模型示例为 `omni-moderation-latest`，也可使用支持的固定版本 `omni-moderation-2024-09-26`。该功能调用 OpenAI 官方 `POST https://api.openai.com/v1/moderations`，不使用聊天模型模拟安全分类。

## 异步处理与覆盖边界

请求侧只提交有界的内部持久化审查任务；后台工作器调用 OpenAI 并处理结果。用户请求不等待审查结论，流式回复也不等待分类完成。队列写入与审查失败不能转换成正常用户请求的错误。

这是一项事后内容审查，不承诺实时拦截，不替代正常鉴权、权限校验、余额结算或其他服务安全控制。队列恢复或重试使用原任务身份，不把同一请求变成新的处罚机会。

当前处理的是能提取的本次文字：API 使用已识别协议中最后一条用户消息的文字，内置助手使用本次用户输入，并将助手回复单独记录。不会把整个请求 JSON 或全部历史对话当成待审文字；未知请求结构不强行提取。系统提示、工具定义和工具结果不在该功能的审查范围。图片、音频、视频、文件二进制和无法提取的内容不属于当前覆盖范围；不能因为 OpenAI 模型支持部分图片分类，就宣称本功能已经审查了图片。

转交人工客服的聊天沿用现有私密客服流程，不经过 OpenAI 内容审查，也不作为该功能的 AI 输入或模型输出记录。

仅对实际提取并成功审查的有界文本作分类。单个任务最多接受 256 KiB UTF-8 文字，长文本按至多 16 KiB 的有效 UTF-8 分块提交；全部批次审查成功后，才合并类别与分数并处理通知、风险或扣款。任何批次失败时，整个任务不作为完成的违规结论处理。

超过任务长度限制的内容明确记录为未完成审查，后台取消该任务，不把截断前缀发送给 OpenAI，也不据此处罚。复杂请求结构、不支持的格式或无法提取的内容仍有覆盖边界；未提取、未审查或部分内容不能被描述为已经全文通过。

## 宽容模式、严格模式与余额

宽容模式对审查命中的用户输入发送站内警告，不扣余额。严格模式也使用站内通知，并按管理员配置的违规类别金额处理用户余额。

一次请求命中多个类别时，只取已配置类别金额中的最高金额处理一次，不累加类别罚款。金额以美元（USD）配置，最多 6 位小数，每类别上限为 USD 1000；未配置或为零的类别不产生扣款。处罚是平台配置的措施，不是 OpenAI 收取的审查调用费，也不是普通模型用量费用。

金额按最小账本单位向下取整，实际扣款不超过配置金额；小于一个账本单位时仅提醒，不扣款。最小账本单位受平台额度换算配置影响，本说明不固定某个美元换算值。

实际扣款最多为处理时可用的正余额：余额不足时仅扣现有正余额，不制造负债，不在以后充值时补扣差额。通知与账目记录区分规则金额和实际扣款，保留请求、类别与对应记录，供用户核对和管理员复核。重复处理同一请求不能再次扣款。

审查处理时会重新核对开关、分组和策略。管理员不应通过事后提高金额对已发生的请求追溯加价；停用、分组变更或策略变化按后台的一致性检查处理。

## 模型输出与风险分

模型输出的分类结果单独记录，用于安全观察和站内提醒。模型生成的内容不归责于用户，不因此扣用户余额，也不计入用户的违规风险统计。

已完成审查的用户输入违规记录会纳入账号的可解释风险分。当前版本按上次管理重置后成功审查的用户输入请求统计；同一账号的同一请求只计一次，已审查请求数是计数，不是概率或分类可信度。违规请求达到 1、2、5、10 次时，审查风险参考分分别为 0.4、0.6、0.8、0.95；没有违规时为 0。最终账号风险分取此分与原有钱包风险分中的较高值，不叠加。

这些阈值是启发式管理规则，不是经过校准的概率。请求失败、返回格式异常、取消、未审查内容和模型输出不作为用户违规增加风险。重置统计视图不删除历史审查与账目回执；分类标记和风险分都不是违法结论。

## 错误、通知与复核

OpenAI 调用超时、不可用、返回格式异常或其他审查失败会记录为审查状态，不能把它们当成内容违规。排队失败也不是审查通过或违规结论。后台重试、取消或失败不应触发违规扣款；未审查也不表示已通过。

警告、扣款回执和相关提示通过站内通知提供，不要求发送电子邮件。通知不公开用户请求正文。用户对类别、金额或风险记录有疑问时，可以通过站内支持或 [support@lmm.best](mailto:support@lmm.best) 申请人工复核；不要附带密码、完整 API Key 或其他凭据。

## 数据处理说明

启用审查的范围内，待审文字经必要的最小化和脱敏处理后会发送给 OpenAI 官方接口。提交内容仍可能包含用户主动写入的个人信息或其他敏感信息；不要提交无权处理的个人资料或秘密。

平台的内部审查队列和审计记录用于执行任务、通知、处理余额、评估风险和复核。保存期限与访问控制遵循现行[隐私政策](https://api.lmm.best/privacy-policy)，本说明不承诺未经实现和核验的留存期限。

OpenAI 的数据处理遵循其适用条款及[官方数据控制说明](https://developers.openai.com/api/docs/guides/your-data)。当前官方表格对 `/v1/moderations` 列出不用于训练、无一般滥用监测留存和无应用状态留存；这不能被扩大成平台及第三方在所有安全或法律场景下均不保存任何信息的承诺。

## 公示与启用

此功能默认全部关闭。管理员在启用严格模式之前，应公开适用分组、违规类别、USD 金额、模式和生效时间，并遵守现行服务条款的重大变更通知要求。当前条款原则上要求重大变更在生效前至少 14 天公示；发布新能力说明不等于自动启用或立即处罚。

生产公告、维护通知、用户协议和隐私政策是已有配置。发布时先读取、备份并保留现有正文，再追加对应说明；不得用仓库模板覆盖其他公告或现行政策全文。公共规则页面只展示必要配置，不公开渠道 Key、用户请求内容或私人审查记录。
