# 商店的 Extore 导入

商店使用 Extore 的 `extore.commerce-import.v1` 和 `extore.product-listing.v1`，通过服务端 OAuth 授权码与 S256 PKCE 读取商家明确授权的商品。此版本是**一次性、只读的商品草稿导入**，不是自动补货或持续同步。

## 使用

1. 升级 Go 后端和前端。站点设置的公开地址必须是正确的 HTTPS origin。
2. 进入商店的卖家中心，选择“从 Extore 导入”。服务地址默认 `https://extore.lmm.best`，可改成其他公开 HTTPS 域名（本版本只允许默认 443 端口）。
3. 展开“连接设置”，复制回调地址。在对应 Extore 的“商城连接”登记本商城及该地址，将得到的公开客户端 ID 填回商城。不需要客户端密钥。
4. 授权读取所选商品。返回后选择一个商品及一个已启用规格，检查资料，选择“填入商品草稿”。
5. 在原有商品编辑器中确认实际售价、支付方式、可见性和商品资料，保存草稿。另行添加卡密库存，经过原有审核流程后上架。

服务地址和公开客户端 ID 按用户保存在浏览器中；无法使用浏览器存储时仍可导入。授权令牌、PKCE verifier 不会进入浏览器存储。

## 映射边界

标题、当前语言的介绍、规格介绍、可用 HTTPS 图片、支持邮箱及兑换链接填入原有商品编辑器。无图不创建占位图。每次选择一个规格作为一个新的商品草稿，不把不同来源按标题合并。

参考价保持原始十进制文本和币种，只用于预览。实际售价输入框保持空白，不执行换汇。不把未兑换卡密数、发行额度或其他来源数字当作可售库存。禁用规格不可导入。私有商品保留私有可见性；不支持私有商品的后端拒绝导入该商品。

完整源资料在折叠预览内展示。原始多语言文本、属性、输入表单、输出定义、教程和修改权益不会自动复制或同步；这些内容继续由 Extore 的兑换流程解释。来源标识在本次草稿预览中显示，不持久保存为同步关联。需要保留额外说明时，由商家在编辑器中确认并补充。

没有 `cards.issue` 申请、自动制卡、自动上架或刷新令牌流程。读取结束或失败后尝试撤销临时授权。若网络故障导致撤销未确认，可在 Extore 的“商城连接”中手动撤销；商城不保留令牌供后续使用。

## 安全与运行

- `/api/store/extore/authorize` 和 `/api/store/extore/catalog` 要求真实登录会话；沿用商店鉴权、限流和请求体限制。
- 一次性 state 绑定账户与会话，PKCE verifier 使用项目现有持久加密机制保存，10 分钟过期。需要稳定配置 `MERCHANT_STORE_ENCRYPTION_KEY`，或保留已有的 `CRYPTO_SECRET` / `SESSION_SECRET` 配置。
- 回调检查完整目标、state、issuer 和重复参数，消费 state 后才交换授权码。授权码和令牌交换不自动重试。回到卖家中心后清除地址栏中的回调参数。
- 发现文档的端点必须属于所选 origin 且使用约定路径。HTTPS 验证证书，不跟随机器接口跳转，不使用环境代理。复用现有受保护连接器，在实际连接时拒绝私有和保留 IP。
- 发现与令牌响应最多 64 KiB，商品目录最多 16 MiB；目录最多 100 个商品、每商品 100 个规格。错误响应不会暴露令牌或底层错误文本。

协议来源：`TokenNotIncluded/extore` 仓库中的 `docs/commerce-import-protocol.md` 和运行时 `extore/commerce_schema.py`。测试使用虚构域名和内存 HTTP 传输，不发行真实卡密。

## 2026-10-09 协议适配修正

- 授权会话优先使用已配置的 `MERCHANT_STORE_ENCRYPTION_KEY`，没有该项时保留 `CRYPTO_SECRET` / `SESSION_SECRET` 的原有顺序。新商店密钥会话使用明确的密文标记；旧的十分钟会话仍按旧配置读取，不尝试其他密钥来掩盖解密失败。非空弱密钥仍拒绝使用。不要为此覆盖、打印或重新生成生产中已有的密钥。
- 未配置安全存储时，在联系 Extore 前返回 `STORE_EXTORE_SECURE_STORAGE`，提示管理员检查配置，不再引导用户反复重试。没有任何合格密钥时仍拒绝明文保存。
- 目录支持上游可省略的描述、名称、币种与标志。未知标题保留空白供商家补充；未知币种不换汇，未知可见性按私有处理。缺少规格 ID 或启用标志的规格只能预览，不能导入。空规格目录可以预览，每商品上限对齐为 100，服务端目录大小上限对齐为 16 MiB。
- 回调仍是原登记的 `/store/manage`，无需重新登记客户端。页面最早加载本地回调脚本，在加载应用前把参数移到本页内存并清理地址栏。回调文档不加载外部跟踪脚本，并使用只允许本站连接和图片的内容策略；该次页面中的外部图片预览会受限，正常重新打开卖家中心后恢复。
- Go 静态前端、软件包 Nginx 与代理前端覆盖配置均提供 `no-store`、`no-referrer` 和回调内容策略。Go 日志去掉回调查询参数，Nginx 排除回调及其来源日志。其他反向代理也必须过滤回调 URL 与 Referer；只升级前端不能替代服务器日志保护。

部署需同时更新 Go、前端及所使用的边缘配置。Nginx 的 `http-map.conf` 和 locations 配置必须一起更新，先通过 `nginx -t` 再重新加载。回调内容策略使用 http 级 `map`，避免在 location 中以 `if` 设置变量导致带查询参数的页面返回 404。本次不修改生产环境变量，不发行卡密，不增加自动上架、持续连接或补货权限。
