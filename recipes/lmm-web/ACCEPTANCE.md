# Web 验收要求

建立页面×角色×状态清单，至少覆盖首页、定价、登录/OAuth、团队/Key、钱包/账单/用量、聊天、商店/订单/退款、工具/助手、管理员和法律页。

1. 每类真实页面在桌面与窄屏检查加载/空/错误/无权限/能力关闭/正常，记录固定版本与新截图；键盘、焦点、标签和减少动效可用。
2. 七语言选择、浏览器 zh-Hans/zh-Hant 归一化、document lang、翻译完整性、金额/日期/时区可理解；不把未知单位显示为零余额。
3. 真实 Core/扩展下登录/撤销/刷新、个人/团队切换、跨租户拒绝；客户端禁用按钮不能替代后端授权。
4. 模型 SSE 的部分输出、终止错误、取消/断流显示正确，缺失 usage 不展示已完成零费用。
5. 商店购买/支付/退款先展示对象、金额、单位与确认；重复点击/刷新后服务端幂等，最终账本与页面一致。
6. capability 不可用时明确阻塞，不展示假成功；匿名/管理员/开发者/团队角色操作分别验证。
7. 静态分发无需 Node 产品服务；新版本资源缓存与 API 错误不导致白页。负载和包体积先建立实测基线。
8. 定价页输入/输出/按次价格分别验证升降六种顺序、合法零、同价稳定顺序、输入数组不变和各类未知价格排末尾；切换分组后以该分组已计算金额排序，不重复应用倍率。旧 `price-low`/`price-high` 链接仍可读取；菜单点击触发对应排序，七语言和窄屏菜单完整。
9. TOKEN/REQUEST 筛选与侧栏计数一致；包含全 fixed、混合 token/fixed、嵌套条件、标签伪装 fixed、无表达式、解析失败和未知版本，失败回退 legacy quota_type。分类结果不构成费用报价。
10. Thinking Machines/inkling 与真实 Kling 模型在列表、厂商筛选、图标和详情中归属一致；新前端自测不能代替旧单体生产目录与部署版本的独立验收。

11. 使用固定实际 Core 的性能数据验证全局 aggregate 优先、不等权分组/时间点的分子分母合并、null 与合法零、partial/无样本/缺样本提示；非流 TTFT 不显示零。覆盖仪表盘、状态页、模型详情/徽标/比较和七语言。组件测试、完整类型检查、构建、真实浏览器分别记录，不互相代替；没有历史性能或完整入口证据时仍显示部分覆盖。

12. 用同一实际 Core、固定合成完整历史来源与真实管理员密码登录核对全站财务：归一化使用12500000、余额5000000时美元分别为25和10；钱包换算配置缺失，或账本每USD3500000、公开点数每USD100000时结果不变。原币种付款/退款/净额、LDC单列、未确认与非法数分别核对；CNY缺汇率仍未知、credits保留精确整数。大数和有符号金额、普通用户拒绝、读取失败与刷新也须保留原有验收。记录真实静态构建、Core版本与新截图，不用组件测试替代浏览器结果。

13. 固定同一前端构建，分别检查 HTML-in-Canvas 支持与不支持路径：连接节点可读、可选择、可点击，键盘焦点与主题/语言切换正常，自定义 Logo 完整；绘制失败可回到 DOM。记录实际浏览器版本、原生渲染标记与截图，不以 API 替身证明原生绘制已通过。

14. 在桌面、390px 和 320px 视口检查首页、认证、价格、指南及代表性控制台：无横向溢出，移动导航/表单/对话可达，金额单位和错误状态保持；减少动态效果、离屏与隐藏时没有持续装饰绘制。共享组件视觉改善不等于逐页面业务验收。

15. 原生钱包与真实 Core/Go 联合核对五 provider 的渠道、Core 报价、用户确认及原订单读取；缺少原生财务 projection 不借用 legacy 换算开放。超 JavaScript 安全整数金额、两位小数、USD/CNY/EUR/LDC、Core credits、测试环境和 Creem 固定商品均准确，FastPay 无可用入口。支付商已收款但 Core 未确认时仍等待，只有账本确认到账才成功。

16. 同一 HTTPS checkout URL 根据显式 GET/POST 合同展示对应链接或表单；POST action 不含原 query，全部 query 字段按原值提交，包括重复字段、空值、中文、URL 参数与签名字符。用户点击前不得打开或提交，非法协议/带凭据地址拒绝，目标与 opener/referrer 隔离有效。真实边缘路径验证支付 Bearer 和 JSON body 保持、GET/POST 回调 query/body 保持且移除认证头；代理 fixture 与真实系统结果分列。

17. 在报价响应丢失、下单响应丢失、重复点击、401、刷新、进程/页面重启、logout/换账号与存储失败时验证原 key/quote/order 不变、财务 POST 不自动重放、有限 GET 轮询可停止。UNKNOWN/review 不新建请求；provider paid 与 Core credited 分开，已 credited/refunded 后只能明确开始下一单。七语言、键盘、窄屏、恢复提示及真实浏览器行为分别记录，组件测试和构建不抵扣最终业务验收。

18. Coinbase 验证关闭/缺配置、启用、test/live、准确 USD 报价及实际 USDC 支付标签、最小金额与大整数、明确确认和合法付款链接。跳转成功后 Core 尚未入账仍显示等待；重复点击、刷新和 UNKNOWN 不另建单，自动退款不可用。七语言、键盘及窄屏均保留支付币种和环境；组件测试、构建、真实浏览器与支付商 sandbox 结果分开记录。

以上是持续验收合同；实际检查绑定源码与命令，由[源码进度列表](https://github.com/TokenNotIncluded/lmm-api-source/blob/main/docs/progress.md)索引。组件自测不能代替浏览器、可访问性、截图或 Web 构建；未执行项目继续 NOT RUN。


渠道排序增补验收：在应用实际十秒缓存配置下执行A首页→B首页→缓存A首页→A后续页，以及缓存后续页→首页→数据变更→原后续页。前者须重新取得A首页摘要；后者须实际发出摘要验证，等待时和409后均不能显示缓存旧行。还需真实Core验证单位、未知/失败观测、换密钥、复制、权限、分页边界及390/320px键盘流程；组件适配器通过不抵扣该浏览器验收。


积分工作区增补：正式钱包入口在未知历史法币估值且有效 credits 余额下，加载真实订阅计划及奖励活动；预览前无写入，购买需明确确认。USD/CNY 偏好下价格、额度、回执及累计用量均保留整数 credits。真实 Core/隔离 PG/固定 bundle 由不同执行者核实购买、续期、未用退款、原键恢复、兑换/签到/红包预算和重启读回；余额不可读、模块不可用、账户变化和权限不足均不伪造成功。组件合成合同测试不能抵扣真实业务验收，也不抵扣 Go 外部充值流程。

站点配置增补验收：固定同一前端版本，覆盖默认配置、旧配置缺字段、全部关闭、单项关闭与重新启用；首页页头、通用页头、窄屏菜单和重复入口保持一致。管理界面真实保存后刷新仍一致，原有 pricing/security requireAuth、文档权限及扩展字段不丢失。自定义名称、历史品牌同名、自定义相对/绝对 Logo、失败 Logo 分别验证。首页地址展示与四种复制示例在自定义域名、端口、前缀下匹配，不带向另一个服务的硬编码域名；无效地址明确不可复制使用。七语言目录提示与点击/键盘/滚动/触摸入口均可用；关闭后没有残余手势，静止时不显示 00%。桌面、390px、320px 无横向溢出。组件/类型/构建和真实 Core/Go 浏览器配置保存分别记录，未执行仍为未验收。
