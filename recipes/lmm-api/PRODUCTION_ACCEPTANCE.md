# 100% 可用与生产可切换的判定

目标只有在 COMPLETION_SCOPE.md 的每一项行为和原有验收要求都有当前冻结输入对应的证据时才完成。不能将以下门类均分成百分比，也不能用源码存在、测试数量、配方结构或健康接口代替。此文件不授权生产操作。

## 迁移边界与切换演练

1. 固定业务范围、候选源码、工具链、依赖、Core/Go/CLI/Web 制品和 schema；逐一核实真实运行进程身份。旧二进制的 schema-manifest 相同只证明安装 schema 一致，不能证明它来自当前完整源码。
2. 冻结授权只读来源、归档、来源行数/字段/序列/单位/UTC、身份映射及目标实例。原始秘密留私有归档；派生财务计划拒绝在任意字段或元数据夹带已知 bearer，不在异常/报告/公开输出泄露。
3. 逐领域对账，源和目标同样非法的 Key 限制字段不能报 matched。即使 stored facts 匹配，也必须独立证明完整导出范围、target 来源、实际权限和单位。源数据未知不得按 0、禁用或默认单位静默补齐。
4. 最终 writer fence、旧后台任务、回调/请求/退款 drain 有真实读回；active writers=0，unknown liabilities=0；未结算/持续权益必须在同一原操作保留和恢复，不再扣一次钱。
5. 制作并实际恢复匹配的备份，验证身份、资金、Key、订阅、历史和序列；写清切换后产生新账本时如何恢复，不能用回退二进制冒充数据可逆。
6. 固定上述证据后在隔离候选完整演练边缘路由/回调切换、真实业务、重启、故障和恢复。生产环境自己的主机/服务/包/凭据/路径及约束需在授权后真实读回；本地通过不证明远端满足条件。
7. 切换预检必须拒绝 `extensions.host_credential="absent"` 的缺失扩展宿主凭据和每个业务权限。core-cutover-preflight 的 READY/safe_to_cutover 只表示受信任输入的合同一致性；必须检查其引用的实际证据、目标、时效和最终组合验收，不能把手写布尔值与合格形状的 hash 当 go/no-go 依据。
8. 用户明确授权生产执行后，按已审核同一候选过程切换与观察；生产业务回读和恢复条件满足才确认。未实际切换时，只能称“具备已证明的切换前提”，并明确未执行项，不称已上线。

## 资源验收

按原质量合同冻结真实 cgroup CPU 硬配额、内存硬上限、数据库/负载器/上游的预算归属。单 Core 与 Core+Go 联合分别验证预热、稳态、过载、慢消费者/取消、恢复及排空。原已定义本地场景为 1CPU/256MiB Core；Core+Go 联合 1CPU/512MiB，数据库和生成器另算。原完整 HTTP/SSE 场景要求 60 秒预热、300 秒稳态、60 秒过载、60 秒恢复、60 秒排空，正常阶段 5RPS、80% JSON/20% SSE，完整成功率至少 99%、P95≤1 秒、P99≤2 秒。需同时满足完整响应与账本断言，不以全部 503、缩小功能或抬高阈值通过。新目标环境须记录同等或更明确的 workload 与门槛，不能把产品 cgroup 通过说成整机预算通过。

## 状态纪律

每项记录 fixed input、expected/observed、真实命令、退出码、日志、数据库/进程/页面证据及独立复验 owner。状态使用 PASS/FAIL/BLOCKED/NOT RUN；合成单元、真实 PostgreSQL、真实进程、浏览器、外部服务和生产环境分别记录。任何必须项未执行、证据缺失或输入漂移，整体保持未完成。禁止通过删断言、success-only mock、增加无依据 skip 或手填回执来满足本文件。
