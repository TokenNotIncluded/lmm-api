# 重建 LMM API

为个人、团队和运营者构建 Language Model Mesh：统一身份、权限、资金和模型入口，并提供 Web 控制台、`lmm` 客户端和独立的业务扩展。保留项目名 `lmm-api` 与品牌语「LMM API · 连接模型与工具，让智能自由流动」。

完整范围见 [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md)，接口细节由递归组件配方承接；验收见 [ACCEPTANCE.md](ACCEPTANCE.md) 与 [PRODUCTION_ACCEPTANCE.md](PRODUCTION_ACCEPTANCE.md)。当前工作只在[源码进度列表](https://github.com/TokenNotIncluded/lmm-api-source/blob/main/docs/progress.md)中维护，构建提示词不保存已完成/未完成的快照。

## 依赖与装配

| 依赖 | 职责 | 集成条件 |
| --- | --- | --- |
| core | Rust 实现的身份、权限、资金、路由与模型请求；离线安装命令与内部 RPC | 无需 Go 即可独立运行；所有模型授权与计费归 Core |
| extensions | Go 实现的商店、客服、工具、助手、运营与支付外部 IO | 使用独立业务库和窄 RPC，不持有 Core 数据库凭据 |
| web | React/TypeScript 静态控制台 | 与真实的 Core 和扩展联合运行；已关闭的能力明确显示为不可用 |
| cli | Rust 用户客户端与授权软件接入 | 使用系统凭据库与 PKCE，支持 JSON/非交互模式、可审阅的动作，并准确报告阻塞原因 |

各组件都依赖完整的 contracts，由其统一类型、权限、单位、版本、幂等与错误。按合同依赖装配，并冻结同一份最终输入；隔离测试与最终联合验收须分别记录。

产品只有三个程序：`lmm-core`、`lmm-extensions` 和 `lmm`；Web 是静态产物。Rust Core 为单个 Cargo 项目，Go 模块与其同属一个宿主，主要语言与职责保持不变。第三方库须使用经审阅并锁定的兼容版本，并核对许可证；不额外引入产品守护进程。

## 产品范围

按产品要求逐项行为交付以下内容：身份、团队与开发者权限；认证与凭据撤销；唯一账本、预算与订阅；模型矩阵与流式恢复；商店、订单、客服与运营；助手、工具与 MCP；安全委托；公开接口；Web 与 CLI。旧路径消失或新能力关闭，都不能成为删减要求的理由；客户端不得自行决定付款方或权限。

支付细节见 [PAYMENT_PARITY.md](PAYMENT_PARITY.md)：五类旧 provider、七个钱包预设和 Linux DO LDC，须分别完成钱包、订阅、商店、退款与配置管理。FastPay 已退役，历史标记与拒绝 fixtures 予以保留。新增的 Coinbase Business 钱包按组件合同实现：USD 报价、同额 USDC、独立验签、一次入账；默认关闭，自动退款也默认关闭，且不混入旧 provider 的恢复矩阵。

Extore 以冻结的商户、版本、文件和原操作完成授权、同步与撤销，并通过真实的两端验收；文档更新不等于授权推送其自动部署分支。真实供应商、历史身份/资金/Key/订阅迁移、全页面浏览器验证和生产切换须分别证明，不得用合成上游、健康检查 200 或配方结构检查来抵扣。

## 环境与运行边界

服务器目标为 Linux amd64/arm64；CLI 目标为 Linux、macOS 与 Windows 的 amd64/arm64。最低浏览器版本及各平台的支持范围以实际验收结果明确。PostgreSQL、操作系统、浏览器、TLS、凭据库、反向代理和外部账号是运行前提，不得伪装成隐藏的配方依赖。已冻结的升级合同中，PostgreSQL 版本与前驱版本约束继续有效。

工具链与最低版本读取固定源码中的声明和锁文件，并核对实际子进程版本；入口文档不复制易过期的开发版本表。运行配置使用 TOML，owner 与 runtime 角色分离；普通启动不建库、不执行 DDL、不自动迁移。新装、首任 owner 创建和既有库升级，都使用显式的 Core 子命令。对真实数据源的只读访问、隔离目标、生产与付费操作，均按用户授权的范围执行。

Web 按 web 配方，呈现简洁、留白充分、层级清晰的界面，保留简体中文、繁体中文、英语、法语、俄语、日语和越南语，并保证时区、单位与错误信息准确。Core 独立运行、扩展停机、数据库故障、并发 SSE、慢客户端和大账本分页，按生产验收合同的资源硬门槛，并与旧实现对照执行。

## 交付与反馈

实现放入独立的源码仓库，以可达提交的 gitlink 接入 `generated/lmm-api-source/`；CLI/providers 保持嵌套归属。先提交并推送，核对远端后再更新父指针；配方不夹带源码。自测、独立复验、候选、安装、发布与部署，各自保留独立的证据。

[ISSUE_MAINTENANCE.md](ISSUE_MAINTENANCE.md) 保存问题单和旧候选的具体行为合同。迁移或关闭旧 PR，不代替对其行为的验收；修复须关联源码、反例和固定输入。

质量快照须分别绑定暂存区的模式/blob、工作区字节、未跟踪项以及子模块，并从基线到暂存区、再到工作区逐层扫描。部分暂存不得漏报；测试期间仅修改暂存区，同样会使证据失效。完整计划保留 Mocklab selftest 的原始报告；失败、空集合、skip 和环境阻断不得记为成功，组件通过也不能代替真实业务验收。

## 站点配置合同

首页、公开页头和重复入口共享有效品牌、公开 API 地址以及 HeaderNavModules。管理员保存后，刷新页面并在多种视口下都须实际生效；保留默认兼容、原有权限和七种语言，隐藏导航不能取代授权。

Core 只向最高管理员 Session 开放 HeaderNavModules 的写入，并声明可写能力。须保留未知的扩展字段，JSON 对象不超过 64 KiB；同一事务内核对版本，并处理批量 expected_values、审计与冲突。公开状态读取已保存的导航和启动配置中的公开地址，设置接口不能覆盖主机地址或 OAuth issuer。数据库支持以追加组件和显式离线升级交付，不改动旧 SQL/函数；须验证数据与权限保留、精确重放、受限 runtime、并发，以及审计失败时回滚。
