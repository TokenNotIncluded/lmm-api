# 重建 LMM API

重建面向个人、团队及运营者的 Language Model Mesh：统一身份、权限、资金与模型调用，向用户提供 Web 控制台和 lmm 客户端，向运营方提供独立扩展业务。保留项目名 `lmm-api` 与品牌「LMM API · 连接模型与工具，让智能自由流动」。这是在建系统的重建要求，不是已完成迁移或生产替代的声明。

## 递归依赖与装配

| 别名 | 职责 | 使用范围 | 集成验收 |
| --- | --- | --- | --- |
| core | Rust lmm-core，唯一身份、权限和资金写入方 | HTTP 模型入口、授权、账本、离线安装命令、内部 RPC | 无 Go 仍可启动；模型请求仅由 Core 鉴权计费 |
| extensions | Go lmm-extensions，独立业务记录 | 商店、客服、工具、助手、运营与支付供应商适配 | 只通过授权 RPC 请求 Core 动作，无 Core 数据库凭据 |
| web | React/TypeScript 静态控制台 | 用户、团队、运营与管理界面 | 与 Core/扩展真实联合测试，能力关闭时正确显示不可用 |
| cli | Rust lmm 客户端 | 发现、诊断、登录、模型与余额读取、受限 Pi 接入 | 系统凭据库、PKCE、JSON 非交互和阻塞动作行为一致 |

每个组件依赖完整的 contracts 配方，统一权限、单位、幂等和错误语义。按 contracts → core/扩展/客户端 → 联合验收顺序构建；可并行开发，验收固定同一组输入。

只有三个产品可执行程序：lmm-core、lmm-extensions、lmm。Web 仅静态产物，不新增产品部署守护进程。Rust Core 保持一个 Cargo 项目，Go 模块属于同一扩展宿主。保留 Rust 核心、Go 扩展、Rust CLI 与 React/TypeScript Web 技术选型；更换主要语言须另获用户决定。库可选择兼容的维护版本，须核对许可证并锁定版本。

## 必须保留的产品行为

个人/团队身份与权限、API Key、会话与撤销，资金预留/结算/退款、预算和订阅，多供应商模型路由、流式输出、工具与助手授权，商店/订单/客服/运营与支付扩展，公开协议、Web 和 CLI。目标范围覆盖现有微服务领域及原明确待验收需求，不以重建为由删除尚未完成的能力；明确分为已观察实现与待完成目标。

外部模型供应商、真实支付、历史资金/订阅/Key 数据迁移、全页面浏览器流程和生产切换仍待独立验收。不得用合成供应商、测试账号登录、200 健康响应或本包结构检查把这些缺口填成成功。Extore 商品同步未完成；不得合并或推送会自动部署的 Extore main。

## 环境与操作边界

服务目标为 Linux amd64/arm64；CLI 为 Linux/macOS/Windows amd64/arm64；Web 为现代浏览器，最低版本未知，须在重建验收时明确。平台列表是交付目标，不是本次实测通过矩阵。PostgreSQL 为外部数据库，现有升级文档涉及 PostgreSQL 18 前置契约，其他版本兼容未知。浏览器、OS、编译器、TLS、凭据库、反向代理、模型/支付账号均为外部前提，不需要将其源码伪装成配方。

已观察开发工具：Rust 1.99.0、Go 1.27.2、Bun 1.3.14、Node 26.10.0、just 1.58.0；这些是仓库配置，不是本轮已安装实测。Core Cargo 声明 rust-version 1.91，CLI 文档声明 1.88+，Go 模块声明 1.25.0；最低版本仍须独立构建确认。

配置采用显式 TOML；运行身份和安装 owner 分离；普通启动不建库、不改结构、不自动迁移。全新隔离库初始化、离线首次 owner 创建和现有库升级使用同一 Core 的明确子命令。禁止连接生产库做验收；不得自动注册生产账号或作真实付费调用。构建、发布、部署和验收分别记录。

## 设计、语言与性能

Web 遵循 web 配方的设计方向，不套通用仪表盘。保留简体中文、繁体中文、英语、法语、俄语、日语、越南语；用户时区、货币/积分、错误、空状态和权限拒绝不能翻译丢失。未有 RTL 语言需求，不宣称已支持 RTL。

核心独立部署、Go 停止时核心模型不受同步依赖阻塞，是架构验收条件。参考低内存单核场景，但本次没有延迟/吞吐/内存预算或基线；禁止写出虚构的性能数字。后续针对并发模型 SSE、慢客户端、扩展停机、数据库故障和大账本分页，固定设备、样本、工具链和源码测量。

完整范围以 COMPLETION_SCOPE.md 的 A01–A10 和 S11 为准；生产可切换必须逐项通过 PRODUCTION_ACCEPTANCE.md。执行 ACCEPTANCE.md；报告成功、失败、阻塞及未运行项。生成的实现应放入独立源码仓库，固定 gitlink 接入 generated/<小写短横线仓库名>/；generated 是容器，不在配方中夹带源码。
