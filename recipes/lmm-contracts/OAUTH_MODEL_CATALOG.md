# OAuth 客户端与动态模型目录

本合同定义产品行为，不代表已部署或已通过独立验收。适用于所有维护中的 LMM OAuth 模型客户端和 Web 控制台。

## 标准与权限

遵循 OAuth Authorization Code + PKCE S256、RFC 9700 安全实践、RFC 8414 授权服务器发现与 RFC 7009 令牌撤销。免密指客户端通过浏览器已有会话或站点身份验证获得授权，无需复制 API Key；不能跳过用户同意、MFA、scope、分组或预算校验。现有客户端、安装和授权家族隔离保持。

模型元数据是版本化的 LMM 扩展合同，不宣称为 OAuth 标准字段。扩展须向后兼容；消费者忽略未知字段，并明确处理缺失能力。

## 目录与元数据

由 Core 提供当前身份与分组实际可用的模型目录，客户端不得维护静态模型白名单或以模型名称猜测能力。模型条目包含调用 ID、原始模型 ID、最大上下文、最大输出、可用协议，以及价格和适用倍率。未知的上下文、价格或倍率保持缺失/null 并显示未知，不伪造成零价或无限上下文。

价格须明确币种、计量单位、输入/输出与缓存方向，以及基础价格或应用倍率后的有效价格；倍率须明确适用维度，不能重复相乘。原始模型 ID 不携带供应商凭据、渠道秘密或无权读取的运营配置。最终计费仍由 Core 权威计算，客户端展示不改变扣费。

插件在授权成功、宿主模型发现/刷新和明确同步时读取服务端目录；模型增删及元数据变化无需重新发布插件即可生效。宿主要求保存配置时，重新同步更新由插件管理的模型项并保留用户其他配置。网络错误不得伪装为成功的空目录，撤销或认证失败不能继续使用旧目录作为有效授权。纯目录刷新不触发真实付费模型调用。

## 用户授权管理

用户可查看自己的客户端授权、权限范围、创建/到期状态及已有安装标识，并撤销单个授权或指定客户端的全部有效授权。操作明确区分单安装与整客户端；其他客户端不受影响。服务端依据当前会话确定用户，不能信任请求中的用户 ID。

客户端撤销覆盖该用户该客户端的相关 access/refresh 家族；撤销后的模型调用、刷新和轮换恢复均拒绝，重新使用需要重新授权。已接纳请求按原账务合同结算，不撤销既有账本。浏览器确认、忙碌、空列表、失败和成功状态完整，七种语言一致；页面不显示 token。

## 验证

以当前目录响应验证所有维护中客户端的动态新增、删除、元数据变化及未知值处理。验证两用户和两客户端隔离、按客户端撤销后的 access/refresh/恢复拒绝，及未撤销客户端仍可用。前端验证授权清单、确认和错误恢复，并检查实际渲染。组件自测、真实宿主验证、独立验收、发布与部署分开记录。
