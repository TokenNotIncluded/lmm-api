安全审查说明

本页介绍功能与处理规则，不代表您的分组已启用审查或扣款。 当前总开关、分组模式与类别金额请查看公开安全规则。未明确配置的分组保持关闭。

1. 异步审查与范围 Asynchronous review and scope

审查任务在后台执行，正常请求与流式回复不等待 OpenAI 的分类结果。这是事后内容审查，不承诺实时拦截，也不替代登录、权限和其他服务安全控制。

当前仅审查本次能提取的文字：API 使用已识别协议中最后一条用户消息的文字，内置助手使用本次用户输入，助手回复单独处理。 不审查整个请求 JSON、全部历史对话、系统提示、工具定义或工具结果；未知请求结构不强行提取。 图片、音频、视频、文件二进制以及无法提取的内容不在本次覆盖范围。 支持长度内的长文本分块审查，全部批次成功后才处理结果。 超限、无法提取或任一批次失败的内容不按完整审查处理，不能仅以前缀认定违规，也不意味着全文已经通过。

转交人工客服的聊天沿用现有私密客服流程，不经过 OpenAI 内容审查，也不作为该功能的 AI 输入或模型输出记录。

示例模型为 omni-moderation-latest。 专门的内容分类会判断支持的安全类别，不保证发现所有滥用行为。

2. 分组模式与余额 Group modes and wallet handling

  • 关闭：对应功能总开关关闭、分组未配置或分组模式关闭时，不进行该功能的内容审查。
  • 宽容模式：用户输入被标记时，仅发送站内警告，不扣用户余额。
  • 严格模式：用户输入被标记时，可按管理员已公示的类别金额从用户余额扣款，并提供站内通知与账目记录。

类别金额以美元（USD）配置。同一次请求命中多个类别时，只取已配置金额中的最高值处理一次，不叠加类别罚款。 未配置或为零的类别金额不产生扣款。这是平台设置的处理措施，不是 OpenAI 收取的审查费。

金额按最小账本单位向下取整，实际扣款不超过配置金额。 小于一个账本单位时仅提醒，不扣款。

实际扣款不超过处理时可用的正余额。余额不足时仅扣现有正余额，不形成欠款，也不在以后充值时补扣。 通知和账目区分规则金额与实际扣款。同一请求不会因重试再次扣款，也不会因事后提高规则金额追溯加价。

管理员应在启用严格模式前公示适用分组、类别、金额和生效时间，并遵守现行服务条款的重大变更通知要求。 发布本说明不会自动启用任何分组。

3. 归责与风险分 Attribution and risk score

已完成审查的用户输入违规记录会纳入账号风险分。 模型输出单独记录，不归责于用户，不因此扣用户余额，也不增加用户的违规风险分。

当前按上次管理重置后成功审查的用户输入请求统计，同一请求只计一次。 违规请求达到 1、2、5、10 次时，审查参考分分别为 0.4、0.6、0.8、0.95；最终账号风险分取此分与原有钱包风险分的较高值。 已审查请求数是计数，不是概率。分类可能误判，这些阈值仅供管理参考，不等同于违法结论或犯罪概率。

4. 审查失败、通知与复核 Failures, notices and review

调用超时、服务不可用、返回格式异常或未审查的内容不按违规处理，不触发违规扣款或风险增加。 审查失败也不意味着内容已经通过。

提醒和扣款回执通过站内通知提供，通知不公开您的请求正文。 如需核对类别、金额或风险记录，请通过站内支持或 support@lmm.best 申请人工复核；不要发送密码、完整 API Key 或其他凭据。

5. 内容与第三方数据处理 Content and third-party processing

在启用审查的范围内，待审文字经必要的最小化和脱敏处理后会发送至 OpenAI 官方 Moderation 接口。文字仍可能包含您主动提供的个人信息；请不要提交无权处理的个人资料或秘密。

平台内部队列与必要审计记录用于完成审查、通知、余额处理、风险统计和复核。 保存期限及相关权利遵循隐私政策。 OpenAI 的处理遵循其适用条款与官方数据控制说明；本页不承诺平台和第三方在所有安全或法律场景下均不保存信息。

模型能力与类别范围请查阅OpenAI Moderation 官方指南。模型支持某种内容类型，不代表平台已提取或实际审查该内容。

English

AI assistant and API content reviews use OpenAI official Moderation models in the background. Both features are disabled by default. Administrators explicitly choose each account group's mode; unlisted groups remain disabled. See current public rules for feature switches, group modes and category amounts.

Requests and streamed responses do not wait for a review verdict. These are post-request reviews of the last identifiable user message in a supported API protocol, or the current assistant input and its output recorded separately. Entire request JSON, full conversation history, system prompts and tool definitions or results are not covered. Unknown structures are not force-extracted. Supported long text is split into chunks, and all batches must succeed before results take effect. Oversized text and failed batches do not produce a completed violation finding. Images, audio, video and binary files are not covered. Partial or missing review does not mean all content passed. Reviewed text is sent to OpenAI after necessary minimization and redaction; personal information may still appear in text you provide.

Chats handed to human support retain the existing private support workflow; they are not sent for OpenAI content review or recorded as this feature's AI input or model output.

Tolerant mode gives an in-site warning without a wallet deduction. Strict mode may charge the highest configured USD amount among matched categories once per request. Unset or zero amounts do not charge. Charges are capped at the available positive wallet balance, create no debt and are not collected later after a top-up. These platform penalties are not OpenAI moderation fees. Model output is recorded separately and never penalizes the user or increases their risk score.

Amounts are rounded down to the smallest ledger unit. Actual charges never exceed the configured amount; amounts smaller than one ledger unit produce only a warning.

Reviewed violations in user input contribute to an explainable account risk score. Since the last administrative reset, each reviewed user request counts once. At 1, 2, 5 and 10 flagged requests, the review scores are 0.4, 0.6, 0.8 and 0.95. The account uses the higher of this score and its existing wallet risk score. Reviewed request counts and these heuristic scores are not probabilities. Provider failures, malformed responses and unreviewed content are not violations and do not produce penalties or risk increases. Classification may be mistaken and is not a legal finding. Warnings and receipts stay inside the site; contact authenticated support or support@lmm.best for human review. Never send passwords or full API keys.

Review records and third-party processing follow the published Privacy Policy and OpenAI data controls. Administrators must disclose affected groups, categories, amounts and effective dates before strict activation, following existing terms for material changes. This notice does not activate any group.
